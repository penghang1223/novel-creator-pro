# 用户反馈（双端共享）

> 记录用户对 Claude 行为的纠正和确认，避免重复犯错。

## 已记录反馈

### 2026-04-18 番茄小说章节字数红线

**问题**：多次交付章节字数远低于番茄平台要求（3000中文字符±200），实际常在700-1500字之间。

**How to apply**：每章正文写完后，**必须先统计中文字符数**。番茄要求：每章 2800-3200 中文字符。低于 2800 → 禁止交付，必须扩写。

### 2026-04-28 有检查清单但执行不到位（反复发生）

**问题**：检查清单中明明写了"生成大纲""创建目录结构"等步骤，但执行时擅自删减——只做卷一细纲、跳过素材目录、漏掉7卷细纲。用户反复指出才补上。

**根本原因**：以为"有了就够用"，没有逐项核对。清单是纸面的，执行是手动的。

**How to apply**：
- 执行检查清单时，逐项打勾，不能"大概齐"
- 增加最终复核步骤（第20步），写正文前回头检查所有文件是否到位
- 检查标准：项目目录下不能有"应该有内容但为空"的文件夹

### 2026-04-28 对话不像人话

**问题**：写出"看你长得贵"这种不像日常口语的表达。人不会说"长得贵"，会说"挺有钱的""一副有钱人样"。

**How to apply**：写对话时，先在心里默念一遍。如果念出来觉得别扭，就换一句。不要追求修辞新奇而牺牲自然度。

### 2026-04-28 不要再犯重复错误

**用户明确指令**："以后不要再犯这种问题"。

**问题回顾**：本次项目立案时连续犯错：
1. 跳步执行检查清单（并行代替串行）
2. 遗漏文件（7卷细纲、素材信息、小说信息格式不完整）
3. AI味自检不到位（精确计时"沉默了两秒"等未被扫描发现）
4. 过度清除常用词（"看到"全部替换为"瞥见"导致文本不自然）

**How to apply**：
- 每次接新项目时，**逐字阅读反馈文件**后再开始
- 检查清单必须逐项打勾，不能"大概做过"
- 第20步"最终复核"不是可选项，是强制项
- 用户反馈中出现"不要""以后"等词时，立即记入feedback

### 2026-04-28 AI味自检漏了"精确量化"

**问题**：32项AI味扫描没发现"沉默了两秒""看了整整两分钟""零点几秒"这类精确计时的表达。人叙述时不会精确到秒/分钟。

**How to apply**：自检时增加一项——检查是否有"精确量化时间"的表达（X秒、X分钟、恰好、刚好），改为模糊自然的时间描述（一下、很久、一瞬间）。

### 2026-04-28 不要过度清除常用词

**问题**：AI味自检时，机械地把"看到"全部替换为"瞥见"，把"很"字几乎清零，导致文本不自然、生硬。

**用户纠正**：不要过度清除这些字，可以有，只要不是那么多就行。

**How to apply**：
- 自检AI味时，目标是"降低频率至自然水平"，不是"清零"
- "看到"：自然文本中必然出现，控制到合理密度即可（非高密度重复）
- "很"：口语中常用，控制到合理密度即可
- 替换原则：只有当重复频率明显影响阅读时才替换，且替换后必须读起来自然
- 宁可保留少量常用词，也不要让文本变得生硬不自然

### 2026-05-22 立项时没读知识库就硬写人设

**问题**：立项《全球游戏化：我的暴击率没有上限》时，完全没读 `knowledge_base/20_Characters/` 就凭自己感觉设计角色——结果职业是烂大街的996程序员、动机没有内部冲突、行为指纹缺乏记忆点。后续重设计时又漏了 `10_WorldBuilding/题材知识库/`，导致角色的游戏体系定位（天赋/技能树/装备/战斗风格）完全缺失。

**根本原因**：CLAUDE.md 里写了"创作前必读知识库"，但执行时跳过了。知识库里有四维动机模型（欲望/恐惧/创伤/缺陷，四维之间必须有内部冲突）、角色原型趋势、人设标签化设计等方法论，全部没用。游戏题材知识包里的"战斗三流派""数值控制""防单机化"等关键设计原则也没参考。

**How to apply**：
- **立项时必须先读知识库**：`60_Platform/平台规则.md` + `20_Characters/` 全部 + `10_WorldBuilding/` 对应题材知识包 + `50_Quality/红线检查/`
- **知识库是参考工具，不是唯一标准**。用它来避免俗套、检查设计是否有内部矛盾，但最终决策由创意判断决定
- 已更新 `.claude/commands/novel-plan.md` 和 `project_bootstrap_pipeline.py` 的输出提示
- **每次重启小说时自动触发**：novel-plan 命令文档已包含知识库预读步骤
- **10_WorldBuilding 不是可选**：题材知识包包含战斗体系设计、数值控制、情节模式等直接影响角色设计的内容，和 20_Characters 同等重要

### 2026-05-22 细纲和设定底座矛盾未发现（赵天宇杀林渊的理由）

**问题**：写第1章时，死亡场景写了"影盟说你是系统异常。异常得删。"——这意味着赵天宇杀林渊是影盟命令，因为暴击系统是异常。但设定底座明确：暴击系统是重生后才激活的，前世根本没有。所以前世影盟不可能因为"暴击系统异常"下令杀林渊。

**根本原因**：写作流程中，**细纲被当作唯一权威来源**，但细纲本身没有和设定底座（创意/设定/角色文件）做交叉验证。细纲卷六 Ch162 写了"赵天宇是被影盟命令击杀林渊的——因为林渊的暴击系统共鸣度在前世也达到了危险值"，这行直接和"暴击系统仅在今生激活"的设定矛盾。写正文时照搬了细纲的错误设定。

**How to apply**：
- **写每章前，必须交叉验证细纲和设定底座**：读细纲对应章节时，同时检查是否与创意文档、角色设定、能力系统设定矛盾
- **核心矛盾点清单**（写章前必查）：
  1. 暴击系统 = 仅今生，前世不存在
  2. 前世赵天宇杀林渊 = 个人动机（嫉妒/打压），不是影盟命令
  3. 影盟 = 今生才盯上林渊（因为暴击系统激活后的异常表现）
  4. 苏曼曼 = 赵天宇安插的眼线，前世两年都是伪装
- **已修复**：卷六 Ch162/163/174 + 循环C3描述全部改写，改为"影盟前世就注意林渊（因自身天赋升B级），但赵天宇杀他是个人恩怨，影盟只是默许"
- **优先级**：和字数红线同等重要——设定矛盾比AI词更致命，因为会让整个故事逻辑崩塌
