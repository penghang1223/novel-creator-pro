# 审稿 Review Skill 设计文档

> **创建日期**：2026-05-05
> **状态**：待批准
> **目标**：创建独立的审稿子技能，对已写章节做深度质量审查，直接利用知识库作为审查标准

## 一、背景与动机

### 现状问题

当前审稿能力分散在多个组件中，没有统一的执行流程：

| 组件 | 能力 | 局限 |
|------|------|------|
| `[10] 审稿评估` (SKILL.md §1227) | 5步检查清单 | 只是几段文字，没有独立 skill 目录，不被执行 |
| `post_write_audit.py` (1209行) | 自动化硬规则 | AI词/对话比/字数/乒乓句——纯规则匹配，不能判断"好不好" |
| `novel_review_and_upgrade.py` (808行) | 完结后扫描 | 只在完结时跑，不适合单章审稿 |
| `评估系统/` (6个文件) | 内容/创意/大纲/结构/设定评分 | 只是参考文档，从未被执行过 |
| `红线系统.md` | 三级红线 | 被审计脚本部分实现，部分是人审 |

**核心问题**：`knowledge_base/40_Writing/` 和 `knowledge_base/50_Quality/` 中有大量可执行的审查规则，但从未在实际审稿中被调用。

### 设计目标

1. **独立子技能**：仿照 `novel-memory-pro/` 模式，创建 `review-skill/` 目录
2. **双模式**：单章精审（深度）+ 批量快审（效率）
3. **知识库驱动**：审查标准直接从知识库原文提取，不依赖速查卡
4. **审查+确认后修复**：输出审查报告，用户确认后才执行修复

## 三、双审查模式

### 3.1 单章精审

| 项目 | 说明 |
|------|------|
| 触发语 | "审一下第N章"、"这章写得怎么样"、"帮我审查这一章" |
| 范围 | 1章 |
| 耗时 | ~5分钟 |
| 深度 | 四维度逐项分析 + 具体段落引用 + 修复建议 |

### 3.2 批量快审

| 项目 | 说明 |
|------|------|
| 触发语 | "审一下第M-N章"、"审查一下这卷"、"全本审查" |
| 范围 | 2-20章 |
| 耗时 | 每章~2分钟 |
| 深度 | 每章快速扫描 + 跨章节一致性分析 |

## 四、执行链

### 4.1 单章精审执行链

```
Step 1: 自动检测（Python脚本，确定性结果）
├── post_write_audit.py → AI词/对话比/字数/乒乓句/钩子密度
├── plot_continuity_checker.py → 剧情连贯性（如适用）
└── 输出：自动检测结果表

Step 2: 深度审查（LLM，读取知识库原文作为评判标准）
├── 对话质感审查
│   ├── 读取：03_人物与对话/对话质感完整框架.md
│   ├── 读取：03_人物与对话/AI对话丰满化技法.md
│   ├── 对照六要素：逐段对话检查表情/心理/听觉/环境/节奏/倾听者
│   ├── 声纹测试：删掉"某某说"能否分辨谁在说话
│   └── 9项审计清单逐条检查
├── 爽点节奏审查
│   ├── 读取：04_场景与描写/爽点设计.md
│   ├── 读取：04_场景与描写/潜台词与张力技法.md
│   ├── 本章是否有小爽点？压抑/释放比例是否7:3
│   ├── 潜台词检查：口是心非/话里有话/干涩检测5问
│   └── 套路检测：对照06_质量校验/套路预判+绕开机制.md
├── 章节结构审查
│   ├── 读取：02_节奏与结构/每章节奏公式与卡章技巧.md
│   ├── 读取：02_节奏与结构/张力曲线设计.md
│   ├── 开头300字是否有冲突
│   ├── 断章是否在有效位置（悬念/打脸前/新冲突/情感高潮/身份揭示前）
│   ├── 是否踩了无效断章（日常/环境/平淡对话后）
│   └── 张力曲线是否合理
└── 去AI化审查
    ├── 读取：05_降AI痕迹/降低AI痕迹.md
    ├── 32项AI味指标逐项扫描
    └── "每段三刀"法则检查

Step 3: 综合评级
├── 每维度10分制打分
├── S/A/B/C/D 五级总评
└── 修复建议按优先级排序（高/中/低）

Step 4: 用户确认
├── 用户说"修"→ 按建议逐条修复，每条修复需用户确认
├── 用户说"过"→ 跳过修复，仅记录报告
├── 用户说"重写"→ 触发重写流程
└── 修复后重新跑 Step 1 验证
```

### 4.2 批量快审执行链

```
Step 1: 每章快速扫描（循环）
├── post_write_audit.py（每章）
├── 对话质感速查（六要素覆盖率，~30秒/章）
├── 爽点速查（有无爽点，~15秒/章）
├── 结构速查（断章有效性，~15秒/章）
└── 输出：每章快扫结果表

Step 2: 跨章节分析
├── plot_continuity_checker.py → 伏笔回收/时间线/因果链
├── character_consistency_checker.py → 角色OOC
├── 张力曲线趋势：章节间张力是否合理起伏
├── 爽点密度：是否符合"每3章1中爽/每10章1大爽"
└── 套路重复检测：最近5章是否用了相同桥段

Step 3: 整体报告
├── 每章评分汇总（表格）
├── 跨章节问题汇总
├── 重点关注清单（需要修复的章节+原因）
└── 整体质量趋势图（可选）
```

## 五、知识库集成（审查标准来源）

**核心原则：审稿用知识库原文，不用速查卡。** 速查卡是写时的快参照，审稿需要原文的完整规则+案例+检查清单。

### 5.1 维度 → 知识库文件映射

| 审查维度 | 知识库文件 | 提取的审查标准 |
|----------|-----------|---------------|
| **对话质感** | `40_Writing/03_人物与对话/对话质感完整框架.md` | 六要素定义、9项审计清单、声纹规则、正反面案例 |
| **对话质感** | `40_Writing/03_人物与对话/AI对话丰满化技法.md` | 5大技法、4条负约束 |
| **爽点节奏** | `40_Writing/04_场景与描写/爽点设计.md` | 强度公式、6步流水线、10种爽点模块、密度规则 |
| **爽点节奏** | `40_Writing/04_场景与描写/潜台词与张力技法.md` | 5种潜台词技法、干涩检测5问、4步润色法 |
| **章节结构** | `40_Writing/02_节奏与结构/每章节奏公式与卡章技巧.md` | 3000字模板、5种有效/无效断章、卡章公式 |
| **章节结构** | `40_Writing/02_节奏与结构/张力曲线设计.md` | 三层高潮、7种张力技法、5章张力模板、张力检查清单 |
| **去AI化** | `40_Writing/05_降AI痕迹/降低AI痕迹.md` | "每段三刀"、8大核心技法、32项AI味检测指标 |
| **套路检测** | `40_Writing/06_质量校验/套路预判+绕开机制.md` | 15种套路+绕开策略、原创性加分项 |
| **红线底线** | `50_Quality/红线检查/红线系统.md` | 三级红线（一级否决/二级约束/三级优化） |
| **人味写作** | `40_Writing/03_人物与对话/人味写作指南.md` | 情绪表达优先级、矛盾特质、偏差行为原则、20条硬性禁止 |
| **剧情连贯性** | `30_Plot/` 相关文件 | 伏笔机制、偏离处理、主线维护 |

### 5.2 执行时读取策略

**单章精审**：Step 2 开始时，按审查维度逐个读取对应知识库文件（~6-8个文件），作为 LLM 审查的"评分标准"。

**批量快审**：Step 1 只读取速查卡做快速扫描；Step 2 跨章节分析时再读取完整知识库文件。

| 章节 | 问题 | 严重度 |

建议优先修复章节：[列表]

### 6.3 评级标准

| 等级 | 条件 | 含义 |
|------|------|------|
| **S** | 全维度≥8，自动检测全通过 | 可直接发布 |
| **A** | 全维度≥7，自动检测全通过 | 质量良好，小修即可 |
| **B** | 无维度<5，自动检测全通过 | 及格，需针对性修复 |
| **C** | 有维度<5，或自动检测未通过 | 需要较大修改 |
| **D** | 多维度<5，或踩红线 | 建议重写 |

## 八、验收标准

1. 对 Ch3 执行单章精审，输出完整审查报告
2. 审查报告中引用了知识库原文的具体规则（不是速查卡）
3. 对话质感审查覆盖了六要素的6个子项
4. 爽点节奏审查检测了本章爽点+密度合规性
5. 章节结构审查验证了断章有效性
6. 去AI化审查引用了32项AI味指标
7. 用户确认后可以执行修复
8. 对 Ch1-Ch3 执行批量快审，输出跨章节分析报告
