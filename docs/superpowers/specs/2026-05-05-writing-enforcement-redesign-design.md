# 写作执行层优化设计方案

> 日期：2026-05-05
> 状态：待审批
> 范围：仅修改写作执行层，不影响菜单功能、记忆系统、发布流水线等

## 一、问题根因

当前系统有 1556 行 SKILL.md + 332 行写作速查卡 + 15 个质量文档，规则体系完善但执行层有三个结构性缺陷：

1. **优先级不分层** — 所有规则都标为"硬门禁"，AI 无法区分致命违规和优化建议
2. **约束注入是一次性全塞** — 写作时 context 同时加载大量文档，关键约束被淹没
3. **Pass 1 → Pass 2 没有程序化断点** — 两遍写作法名存实亡，AI 倾向于合并执行

## 二、设计方案：三层约束 + 状态机

### 2.1 架构概览

```
                    ┌─────────────────────┐
                    │  写作宪法 (~80行)    │  ← 每章必带，5条红线
                    │  永远在 context 顶部  │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │ 动态约束块 (按场景)   │  ← 从速查卡+档案提取
                    │ 本章适用的 5-8 条规则 │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
         ┌─────────┐    ┌──────────┐    ┌──────────┐
         │ Pass 1  │───▶│ Gate 检查 │───▶│ Pass 2   │
         │ 剧情稿   │    │ Python脚本│    │ AI词清理  │
         └─────────┘    └──────────┘    └──────────┘
              │          不通过→重写         │
              │                             ▼
              │                        ┌──────────┐
              │                        │ 完整审计  │
              │                        │ post_write│
              └────────────────────────▶│ _audit.py│
                                        └──────────┘
```

### 2.2 不变的模块

| 模块 | 状态 | 原因 |
|------|------|------|
| SKILL.md 菜单功能 [0]-[12] | 不变 | 独立于写作执行层 |
| SKILL.md 自动触发规则 | 不变 | 触发逻辑不变 |
| novel-memory-pro | 不变 | 写前/写后操作，不涉及写作过程 |
| 审计脚本核心逻辑 | 不变 | 仍是写后完整审计 |
| 发布流水线 | 不变 | 完全独立 |
| 写作速查卡 | 不变 | 仍是"怎么做"的参考 |
| 评估系统 | 不变 | 独立流程 |

## 三、组件详细设计

### 3.1 写作宪法 (新增)

**文件**: `novel_creation_promax/references/writing_constitution.md`
**大小**: ~80行
**用途**: 每章写作时永远在 context 顶部的底线规则

从现有 1556 行 SKILL.md + 332 行速查卡 + 15 个质量文档中提炼，只保留"出现即废"的硬规则。

#### 第一条：原创性红线

- 不得抄袭/高度模仿任何已发表作品
- 不得出现元叙事工艺术语：切面、旁白、镜头、转场
- 不得用代码块格式写正文

#### 第二条：字数与结构红线

- 每章字数符合本项目设定（从 `novel_state.json` 的 `word_count_range` 读取，未设置时按平台默认：番茄 2800-3200 / 起点 2000-4000 / 知乎 3000-5000）
- 前 300 字必须有冲突/悬念/动作（禁止平淡环境开场）
- 章末必须断在悬念/冲突处（禁止平淡收束）
- 严格在细纲截断点停笔，不蹭下一章内容

#### 第三条：AI 味红线（Pass 2 必清零）

绝对禁止词（出现即废）：从而、以此、进一步凸显、这表明、这说明、这反映了、总而言之、不言而喻、他是一个...的人

高危限制词（单章 ≤3 次）：突然、微微、沉默、感觉、嘴角、然而、或许

七大反模式（写中自检）：计时器心理、废话对话、凑字数重复、乒乓球短句（≥5 句纯对话）、通用动作（笑了笑/皱了皱眉/叹了口气）、直白情绪命名、套路化结尾

#### 第四条：对话红线

- 对话占比 ≥ 25%
- 每段对话场景至少覆盖 2-3 个六要素（表情微反应/心理独白/听觉细节/环境烘托/节奏留顿/倾听者反应）
- 纯对话超过 3 轮必须插入动作/环境细节
- 禁止使用"他说""她问道"作为对话标签（用动作锚点代替）
- 禁止角色完整回答对方问题（要有回避/沉默/转移）
- 每句对话必须附带面部表情/眼神/微反应

#### 第五条：人物红线

- 每个核心角色必须展现至少一个"矛盾特质"
- 禁止"形容词堆叠式"人物描写
- 情感表达优先级：行为 > 生理反应 > 心理活动 > 直接命名
- 禁止角色所有行为都与其主标签一致
- 禁止角色总做"最优选择"

### 3.2 动态约束注入模板 (新增)

**文件**: `novel_creation_promax/references/chapter_constraint_template.md`
**大小**: ~40行
**用途**: 预组装本章约束，直接注入写作 prompt（约 100-150 tokens）

替代原来 AI 从 10 个文件手动"约束组装"的过程。

```markdown
【第N章 写中约束】

== 红线（写作宪法已加载，此处仅列本章高危项）==
• 本章字数目标：{从 novel_state.json 读取}
• 截断点：{从细纲读取}
• 标题关键词：{必须在正文中出现}

== 人物约束 ==
• {角色A}：矛盾特质={X/Y}，行为指纹={...}
  本章负面约束：{...}
• {角色B}：矛盾特质={X/Y}，行为指纹={...}
  本章负面约束：{...}

== 对话约束 ==
本章对话场景类型：{权力博弈/日常/情感}
适用技法：{回避/指桑骂槐/环境打断}
声纹要求：{A 短句为主/B 长句回忆式}

== 节奏约束 ==
本章类型：{推进章/铺垫章/高潮章}
爽点设计：{本章小爽点，压抑→释放方式}
情绪曲线：期待({N}) → 压制({N}) → 反转({N}) → 释放({N})

== 去AI约束（Pass 2 重点）==
本章高危词：{从上章审计结果继承}
速查卡 §七 三刀法则：本章重点"刀"哪几段
```

**填充方式**：硬门禁 2.5（写中约束组装）从"手动填表"改为自动填充此模板。可由 `pre_write_check.py` 的输出或新增辅助脚本完成。

### 3.3 writing_gate.py (新增)

**文件**: `novel_creation_promax/scripts/writing_gate.py`
**大小**: ~150行
**用途**: Pass 1 → Pass 2 之间的轻量检查，程序化拦截

#### 用法

```bash
python novel_creation_promax/scripts/writing_gate.py \
  --chapter "novel_output/七猫/她眼里有我的未来/正文/第003章-xxx.md" \
  --novel-dir "novel_output/七猫/她眼里有我的未来/"
```

#### 检查项（5项，全部通过才放行）

| # | 检查项 | 数据来源 | 失败条件 |
|---|--------|---------|---------|
| 1 | 字数检查 | `novel_state.json` → `word_count_range` | 中文字符数不在范围内 |
| 2 | 章节边界检查 | `novel_state.json` → `next_chapter_hook` | 当前章末尾出现下一章核心事件 |
| 3 | 乒乓球对话检查 | 正文扫描 | ≥5 行连续纯对话无描写 |
| 4 | 绝对禁止词速检 | 写作宪法第三条黑名单 | 任何一个出现 |
| 5 | 对话占比速检 | 引号/对话标记行数 / 总行数 | < 25%（WARN，不阻断） |

#### 退出码

- `0` = 通过，可进入 Pass 2
- `1` = 不通过，需重写/修复

#### 与现有脚本的关系

| 脚本 | 时机 | 检查范围 | 动作 |
|------|------|---------|------|
| `pre_write_check.py` | 写前 | 9问评分 | 不变 |
| **`writing_gate.py`** | **Pass 1→2 之间** | **5项速检** | **不通过→重写** |
| `post_write_audit.py` | 写后 | 完整审计 | 不变 |

#### 设计要点

- Gate 只检查 Pass 1 阶段该管的事（字数/边界/乒乓球/绝对禁止词）
- 高危词（突然/微微/沉默）故意不在 Gate 检查——Pass 1 本来就不管 AI 词
- 字数范围从 `novel_state.json` 读取，不写死，适配不同平台

### 3.4 SKILL.md 硬门禁重构 (修改)

**文件**: `novel_creation_promax/SKILL.md`
**变化**: 硬门禁部分从 ~400 行精简到 ~100 行，其他部分不动

#### 现有结构（将被替换）

```
硬门禁 0: 约束感知内建（60行）
硬门禁 0.5: 章节驱动引擎（20行）
硬门禁 1: 9问必答（8行）
硬门禁 2: 写前5项检查（12行）
硬门禁 2.5: 写中约束组装（50行）
硬门禁 2.6: 套路预判（30行）
硬门禁 2.7: 物理状态追踪（25行）
硬门禁 2.8: 设定完整性审查（25行）
硬门禁 2.9: 动作流大纲（50行）
硬门禁 0.1: 两遍写作法（50行）
硬门禁 3.5: 人物矛盾性+情感真实性（40行）
硬门禁 3.6: 潜台词与张力（40行）
硬门禁 3.7: 行为指纹追踪（25行）
硬门禁 4: 写后快速扫描（25行）
硬门禁 5: 对话干涩检测（35行）
```

#### 重构后结构

```markdown
## ⛔ 写作流程（状态机）

**写作底线规则见 `references/writing_constitution.md`（写作宪法），每章必读。**

### 阶段 0：写前准备

1. **加载写作宪法** → `references/writing_constitution.md`
2. **9问必答** → `pre_write_check.py`，总分 ≥ 70 分
3. **写前5项检查**：AI词黑名单已加载 / 上一章已读取 / 人物对话档案已加载 / 标题关键词已提取 / 前300字有冲突
4. **约束组装** → 从 `references/chapter_constraint_template.md` 自动填充本章约束
5. **套路预判** → 参照速查卡 §九，列出本章可能涉及的套路+绕开策略

未完成以上任何一项 → 禁止开始写正文。

### 阶段 1：Pass 1 剧情稿

**目标**：写出完整剧情逻辑，不管 AI 词。

**规则**：
- 写的时候完全忽略 AI 词
- 专注于：剧情推进、角色行为逻辑、章节边界、对话信息量
- 每 300-500 字自检：有没有无聊？有没有重复？有没有推进？
- **对话写作参照**：速查卡 §二对话六要素 + §三对话五大技法
- **爽点节奏参照**：速查卡 §五爽点设计

**禁止在 Pass 1 做的事**：不检查 AI 词、不检查对话比例、不做风格校准。

### → Gate 检查（writing_gate.py）

```bash
python novel_creation_promax/scripts/writing_gate.py --chapter {文件} --novel-dir {目录}
```

5 项速检：字数 / 章节边界 / 乒乓球对话 / 绝对禁止词 / 对话占比。
不通过 → 回到 Pass 1 修复对应问题。

### 阶段 2：Pass 2 AI 词清理

**目标**：在保留剧情逻辑和对话风格的前提下，清理 AI 词。

**规则**：
- 以 Pass 1 输出为基准，只改词汇，不动叙事结构
- 对话修改保证：角色说话方式不变
- 如果替换导致语义不通，跳过该替换
- **去AI化参照**：速查卡 §七"每段三刀"法则 + §八 20 条硬性禁止

### → 完整审计（post_write_audit.py）

不通过 → 定点修复，不重写全章。

### 阶段 3：记忆同步

`memory_manager.py sync-chapter` → 更新记忆。
```

#### 精简内容的去向

| 原硬门禁 | 去向 |
|----------|------|
| AI味七大反模式 | 移入写作宪法第三条 |
| 人物矛盾性/情感真实性 | 移入写作宪法第五条 + 动态约束模板 |
| 行为指纹追踪 | 移入动态约束模板的人物约束 |
| 潜台词与张力 | 移入动态约束模板的对话约束 |
| 物理状态追踪 | 保留在 SKILL.md 作为参考文档（非门禁） |
| 设定完整性审查 | 保留在 orchestrator.md（Stage 2 用） |
| 动作流大纲 | 保留在速查卡 §六（按需注入） |
| 章节驱动引擎 | 整合进阶段 0 第 4 步（约束组装） |

## 五、回滚方案

如果优化后效果不理想：

1. `git revert` 回到当前版本
2. 新增的 3 个文件可直接删除，不影响其他模块
3. SKILL.md 硬门禁部分的修改可通过 git 恢复原始版本

由于不涉及数据格式变更（novel_state.json、memory schema 不变），回滚不会丢失任何创作数据。
