# 小说专业审稿系统（行业级全覆盖版）

## 任务目标
- 本 Skill 用于：对小说进行行业级审稿，完整覆盖14个核心维度
- 核心原则：**找出"哪里会让读者弃书"**
- 能力包含：
  - 6大类完整检查（商业/结构/人物设定/连续性/表现/逻辑合规）
  - 14个方面全覆盖（标题、开头、剧情、节奏、人物、世界观、连续性、叙事、对话、语言、逻辑、情绪、商业、合规）
  - AI写作特征检测与去除
  - 常见弃书点诊断
  - 综合问题定位与修改建议
- 触发条件：用户提出"审稿"、"检查"、"评估"、"弃书点"、"AI味检测"等需求

## 核心审稿维度（6大类）

### 第一类：商业（25分）👉 最重要
**核心问题：用户点不点？用户走不走？**
- 标题吸引力（5分）：钩子、题材传达、点击欲、平台风格
- 开头钩子（5分）：快速进入冲突（≤1000字）、核心事件、避免世界观堆砌
- 爽点密度（10分）：情绪起伏、爽点有效性、打脸/反转成立、持续刺激
- 章节结尾钩子（5分）：悬念、吸引继续读

**判定标准**：
- 20+：强上头，有追读潜力
- 15-20：可读但不爆
- <15：大概率扑街

---

### 第二类：结构（20分）
**核心问题：骨架是否稳固？节奏是否合理？**
- 主线清晰度（5分）：目标清晰、贯穿全文、容易理解
- 单章结构完整（5分）：每章目标→冲突→结果
- 节奏合理（5分）：快慢合理、信息释放均衡、爽点间隔合理
- 高潮分布（5分）：高潮分布合理、有铺垫、足够震撼

**核心看**：有没有"水"和"乱"

---

### 第三类：人物与设定（15分）
**核心问题：人物是否立得住？设定是否自洽？**
- 人物动机清晰（5分）：主角动机明确、合理、足够强
- 人物一致性（5分）：性格稳定、不OOC、行为符合性格
- 世界观合理性（5分）：规则清晰、自洽不打脸、被剧情正确使用

**判定标准**：
- 低于10分：人物基本是"工具人"

---

### 第四类：连续性（15分）⚠️ AI最容易崩的点
**核心问题：前后是否一致？**
- 时间线一致（5分）：时间线无矛盾、跨度合理、顺序正确
- 人物关系一致（5分）：人物关系前后一致、发展自然
- 伏笔与记忆（5分）：伏笔不遗忘、不冲突、事件被记住

**判定标准**：
- 低于10分：连续性严重错误，读者失去信任

---

### 第五类：表现力（15分）
**核心问题：读起来"像不像人写的"？**
- 画面感（5分）：画面感强、描写具体、场景有画面
- 情绪表达（5分）：情绪到位、有层次、真实
- 对话质量（5分）：对话自然、推动剧情、符合人物性格
- **AI味检测**：30+指标，影响整体表现力评分

---

### 第六类：逻辑与合规（10分）⚠️ 一票否决项
**核心问题：逻辑是否成立？是否可发布？**
- 因果逻辑（5分）：因果成立、行为合理、推理/战斗自洽
- 合理性（3分）：不强行推进、行为有动机
- 合规风险（2分）：无违规内容、无敏感词、平台可发布

**判定标准**：
- 合规风险存在：一票否决，禁止发布
- 连续性严重错误：禁止发布

### 第六类：逻辑与合规
**核心问题：逻辑是否成立？是否可发布？**
- 逻辑合理性：因果成立、行为合理、不强行推进、推理/战斗自洽
- 商业化能力：平台套路、持续更新潜力、长线钩子、卖点清晰
- 合规与风险：违规内容（色情/暴力/政治）、敏感词、平台可发布

## 操作步骤

### 标准审稿流程

#### 步骤1：执行6大类评分（100分制）

按照以下权重进行评分：
```
总分 = 商业(25) + 结构(20) + 人物设定(15) + 连续性(15) + 表现(15) + 逻辑合规(10)
```

**详细评分标准**见 [references/评分体系.md](references/评分体系.md)

#### 步骤2：问题等级分类

**问题等级定义**：
- **High（致命）**：影响阅读/逻辑崩/无钩子 → P0弃书级
- **Medium（重要）**：影响体验但不致命 → P1流失级
- **Low（优化）**：文风/细节 → P2优化级

#### 步骤3：自动决策

**决策规则**：

🟢 **可发布（直接用）**
- 总分 ≥ 85
- 且无High严重问题

🟡 **优化后发布**
- 总分 70-84
- 或存在 ≤2个High问题
- **操作**：做局部修改

🔴 **必须重写**
- 总分 < 70
- 或商业性 < 15
- 或结构 < 12
- 或连续性 < 10
- **操作**：不要修，直接重写

⚫ **禁止发布（硬规则）**
- 合规风险存在
- 或连续性严重错误（<8分）
- **操作**：禁止发布

#### 步骤4：生成修改优先级

**修改顺序（必须遵守）**：
1. 商业问题（不吸引人）→ 开头钩子、爽点密度
2. 结构问题（看不下去）→ 节奏、主线
3. 连续性（崩）→ 时间线、设定一致
4. 逻辑 → 因果、行为合理
5. 表现 & 文风 → 画面感、对话、语言

**顺序错了 = 白改**

#### 步骤5：输出JSON格式报告

```json
{
  "total_score": 78,
  "dimension_scores": {
    "commercial": 18,
    "structure": 14,
    "character_world": 12,
    "continuity": 13,
    "narrative": 11,
    "logic": 10
  },
  "decision": "revise",
  "fatal_issues": [
    "开头缺乏冲突",
    "第3段节奏拖沓"
  ],
  "priority_fixes": [
    {
      "issue": "开头无钩子",
      "action": "前300字引入冲突事件",
      "severity": "high"
    },
    {
      "issue": "爽点不足",
      "action": "增加一次反转或打脸",
      "severity": "high"
    }
  ]
}
```

### 动态权重调整（不同小说类型）

根据小说类型调整权重：

**爽文**
- 商业 ↑（30分）
- 结构 ↑（25分）
- 连续性 ↓（10分）
- 逻辑 ↓（5分）

**悬疑**
- 逻辑 ↑（20分）
- 结构 ↑（25分）
- 商业 ↓（15分）
- 爽点 ↓（0分）

**恋爱**
- 表现力 ↑（25分，情绪表达10分）
- 人物 ↑（20分）
- 商业 ↓（15分）

详见 [references/评分体系.md](references/评分体系.md)

## 使用示例

### 示例1：新人小说完整审稿
- 场景/输入：作者完成第一部小说，希望全面检查并获取发布决策
- 预期产出：
  - 6大类评分（商业/结构/人物设定/连续性/表现/逻辑合规）
  - 总分和自动决策结果（可发布/优化后发布/必须重写/禁止发布）
  - High严重问题清单和修改优先级
  - 综合报告（Markdown + JSON）
- 关键要点：
  - 执行完整的6大类评分（100分制）
  - 检查开头钩子（前1000字是否快速进入冲突）
  - 检查连续性（AI最容易崩）
  - 执行AI味专项检测，影响表现力评分
  - 检查合规风险（一票否决）

### 示例2：AI写作的爽文第10章自动决策
- 场景/输入：AI生成的爽文第10章，要求自动判断是否可发布
- 预期产出：
  - 使用爽文动态权重（商业30+结构25+连续性13+表现15+逻辑5）
  - 评分结果（总分）和自动决策
  - AI味评分（影响表现力）
  - 修改建议和预计时间
- 关键要点：
  - 爽点密度重点评估（标准：每8-12章1个爽点）
  - 商业性权重提高（30分）
  - 连续性检查（时间线、设定一致）
  - AI味检测（句式单一、对话生硬等）

### 示例3：弃书点诊断与评分
- 场景/输入：作品数据不好，读者流失快，需要找出弃书原因并评估
- 预期产出：
  - 6大类评分
  - 弃书风险评级（低/中/高/极高）
  - 弃书点定位（前3章/中期/长期）
  - 修改路线图和预计时间
- 关键要点：
  - 重点检查：开头（前3章）、节奏、爽点、情绪
  - 分析每个弃书风险点
  - 提供针对性的优化方案

## 执行Prompt

### 三层Prompt架构

本Skill提供三层Prompt模板，用于不同场景的审稿执行：

#### 1️⃣ 主审稿Prompt（核心）
**用途**：完整审稿，输出稳定评分 + 可执行修改方案 + 自动决策

**特点**：
- 100分制评分（6大类维度）
- JSON格式输出
- 自动决策（publish/revise/rewrite/reject）
- 具体问题和可执行建议

**调用方式**：
- 输入：标题、正文、大纲、人物状态、世界观规则、目标类型、目标平台
- 输出：JSON格式的评分、问题、修改建议

**详细内容**：见 [references/执行Prompt.md](references/执行Prompt.md)（主审稿Prompt章节）

---

#### 2️⃣ 维度细化Prompt（可选增强）
**用途**：让评分更稳定，防止评分飘移

**特点**：
- 6大维度评分细则
- 明确评分标准（0-3/4-6/7-8/9-10）
- 防止漏项和误判

**调用方式**：
- 拼接到主审稿Prompt后面使用
- 提升评分稳定性

**详细内容**：见 [references/执行Prompt.md](references/执行Prompt.md)（维度细化Prompt章节）

---

#### 3️⃣ 低成本版Prompt（批量筛选）
**用途**：批量筛稿，快速识别垃圾内容

**特点**：
- 快速评估
- 低成本
- 输出：总分、是否值得继续、最大问题（最多3条）

**调用方式**：
- 用于第一轮筛选
- 低分作品直接淘汰，不进入主审稿

**详细内容**：见 [references/执行Prompt.md](references/执行Prompt.md)（低成本版Prompt章节）

---

### 调用流程

**标准流程**：
1. 低成本审稿（筛选垃圾）
2. 主审稿（精评）
3. 输出修改方案
4. 喂给写作Agent重写

**成本优化技巧**：
- 短内容（<3000字）→ 全量评估
- 长章节（>3000字）→ 只评前1500字 + 结尾
- 低分作品（<60分）→ 不进入下一轮

---

### 稳定性关键

1. **强制JSON**：必须输出JSON格式，如果不是则重新输出
2. **限制输出长度**：issues数组最多10个，防止成本爆炸
3. **禁止模型改文**：明确禁止"改为"类表述，只允许指出问题和给出可执行动作

---

### 进阶方案

**Meta Review二次检查**：
- 第二个模型检查评分是否合理、是否漏掉关键问题
- 适用于高价值作品和重要决策

**详细内容**：见 [references/执行Prompt.md](references/执行Prompt.md)（进阶方案章节）

## 核心原则

### 原则1：自动决策
**这套评分系统的价值不在"打分"，而在：能不能自动决定"发 / 改 / 重写 / 禁止"**
- 总分 ≥ 85且无High严重问题：🟢 可发布
- 总分 70-84或≤2个High问题：🟡 优化后发布
- 总分 < 70或商业<15或结构<12：🔴 必须重写
- 合规风险或连续性<8分：⚫ 禁止发布

### 原则2：找出弃书点
**审稿不是"看哪里写得好"，而是找出"哪里会让读者弃书"**

### 原则3：评分清单化
使用完整的6大类评分清单（100分制），确保客观量化每个维度

### 原则4：优先级驱动
修改顺序必须遵守：商业→结构→连续性→逻辑→表现（顺序错了=白改）

### 原则5：连续性优先
连续性是AI最容易崩的点，也是读者最容易弃书的原因，必须优先检查

### 原则6：合理≠优秀
即使内容"合理"（如日记碎片化），如果影响阅读流畅度，仍需标记为问题

### 原则7：动态权重
不同小说类型使用不同权重（爽文/悬疑/恋爱），提高评分准确性

---

## 注意事项

1. **必须执行完整检查清单**：60+检查点不能跳过，确保无盲区
2. **连续性是重点**：AI最容易在连续性上出错，必须重点检查
3. **每个问题都要评估弃书风险**：这个问题会让读者弃书吗？
4. **AI味检测整合到表现类**：不要单独处理，作为表现层的一部分
5. **优先级排序**：P0→P1→P2，确保先解决致命问题
6. **平台适配**：根据目标平台调整检查重点（见6大类完整检查清单）
