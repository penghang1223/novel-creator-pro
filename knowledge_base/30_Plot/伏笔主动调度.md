# 伏笔主动调度系统

> 从"被动记录"到"主动调度"。伏笔不再靠记得，而是被系统主动告诉你"现在该处理哪个伏笔"。

---

## 伏笔分类体系

| 维度 | 分类 |
|------|------|
| **类型** | 事件伏笔、人物伏笔、关系伏笔、设定伏笔、情感伏笔 |
| **重要性** | 主线伏笔、支线伏笔、细节伏笔、隐藏伏笔（惊喜反转） |
| **时间跨度** | 短期（1-3章回收）、中期（5-10章）、长期（全书贯穿）、终极（结尾揭晓） |

## 伏笔状态机

```
pending → planted → 线索增强 → 接近回收 → resolved
```

状态迁移：
- `pending` → 埋设到章节中 → `planted`
- `planted` → 推进新线索 → `planted`（更新线索）
- `planted` → 回收完成 → `resolved`

## 主动调度逻辑

每章创作前自动检查：

1. **即将到期**（deadline ≤ 当前章 + 3）→ 强制回收，优先级 CRITICAL
2. **高优先级伏笔** → 建议推进，优先级 HIGH
3. **长期未推进**（埋设后 > 5章无动作）→ 提醒推进，优先级 MEDIUM
4. 每章最多处理 **3 个伏笔**，按优先级 + 截止时间排序

## 伏笔记录格式

| 字段 | 说明 |
|------|------|
| id | 唯一标识，如 `F_001` |
| type | 事件/人物/关系/设定/情感 |
| importance | 主线/支线/细节/隐藏 |
| time_span | 短期/中期/长期/终极 |
| content | 伏笔内容 |
| planted_chapter | 埋设章节 |
| target_chapter | 计划回收章节 |
| deadline_chapter | 最晚回收章节 |
| hint_clues | 已有线索列表 |
| status | pending/planted/resolved |

## 调度输出格式

**强制回收提示**：
```
【强制】本章必须回收伏笔 F_001
- 内容：主角捡到一块神秘玉佩
- 已埋设：第3章 → 原计划回收：第15章
- 已有线索：玉佩刻有古文、夜间发光
- 要求：必须与前文线索逻辑闭环
```

**建议推进提示**：
```
【建议】本章可推进伏笔 F_002
- 内容：配角真实身份
- 已埋设：第5章
- 推进方式：给出新线索或暗示
```

## 伏笔时间线可视化

```
第1章    第5章    第10章    第15章    第20章
  ↓        ↓        ↓         ↓         ↓
[埋设]───[线索]───[增强]───[回收]───[影响]

F_001 事件伏笔（主线/长期）
F_002 人物伏笔（支线/中期）
```

## 长篇伏笔铁律

1. 每章至少埋设 1-2 个新伏笔
2. 每章至少推进/回收 1-2 个旧伏笔
3. 写完后更新伏笔状态
4. 不允许伏笔"遗忘"（超过 deadline 未处理 = 违规）

## 伏笔回收评估

- **完整性** = 已回收线索数 / 总线索数 × 100%
- **合理性** = 逻辑自洽性 + 读者可验证性
- **影响力** = 对剧情影响程度 + 对读者冲击程度
