# 叙事引擎

> 工业级可控叙事引擎。从"依赖模型"到"约束模型"。

---

## 创作前：State Engine 初始化

每次新创作必须先建立 `state.json`，包含：

```json
{
  "meta": { "title": "小说标题", "total_chapters": 50, "current_chapter": 0 },
  "worldview": { "time_period": "时代", "location": "主要地点", "key_rules": [] },
  "characters": {
    "protagonist": {
      "name": "主角名",
      "core_goal": "核心欲望",
      "fatal_flaw": "致命缺陷",
      "current_state": { "location": "", "emotion": "", "knowledge": [], "abilities": [] },
      "dialogue_style": "毒舌/神回/话废/正常"
    }
  },
  "foreshadowing_engine": { "pending": [], "planted": [], "resolved": [] },
  "pace_controller": { "current_chapter": 0, "expected_tension": 0.5, "tension_history": [] },
  "style_controller": {
    "narrative_voice": "说书人/猫腻/古龙/金庸",
    "sentence_length": { "min": 8, "max": 25, "avg": 15 },
    "dialogue_ratio": { "min": 0.3, "max": 0.5, "target": 0.4 },
    "forbidden_words": ["然而", "此外", "总而言之"],
    "required_elements": ["具体动词", "感官细节", "潜台词"]
  }
}
```

## 章节续写工作流（四角色分离）

| 角色 | 职责 | 限制 |
|------|------|------|
| **planner** | 结构规划、大纲设计、伏笔布局 | 不写正文，不审查 |
| **writer** | 正文生产、续写、改写、返修 | 单章最多改 2 次，仅自审字数 |
| **checker** | 质量审查、问题分级、修改建议 | 不直接改正文，有最终否决权 |

**标准流程**：planner → writer → checker
**续写流程**：writer → checker
**返修流程**：checker → writer → checker（最多 2 次）

## 创作中执行步骤

1. **planner 预写分析** — 读取 state.json，输出 200 字写作策略
2. **RAG 检索上下文** — 实时状态层 + 短期案层（近 5 章）+ 向量检索层
3. **伏笔调度** — 即将到期 → 强制回收；高优先级 → 建议推进；长期未推进 → 提醒
4. **节奏分析** — 对比 expected vs actual tension
5. **生成结构化 Prompt** — 组装创作指令
6. **writer 生成正文**
7. **checker 程序校验** — 字数、结构、伏笔、一致性、风格
8. **提取章节摘要 + 更新 state.json**

## RAG 记忆架构

| 层级 | 存储 | 检索方式 | 用途 |
|------|------|---------|------|
| 向量长期记忆 | 所有章节向量化片段 | 语义相似度 | 查找相关情节 |
| 短期摘要 | 每章结构化摘要 | 滚动 5 章 | 回顾近期发展 |
| 实时状态层 | 当前人物/伏笔/悬念 | 直接访问 | 确保连贯性 |

**当摘要超过 8000 字时**执行压缩：保留开头 3 章 + 最后 3 章不压缩，中间章节只保留最新属性、最新关系、核心事件结果。

## 关键原则

1. **规则嵌入 prompt** — 不只是写在文件里，关键规则必须写进每次创作的 prompt
2. **年龄/时间/空间是血线** — 写错不可逆，必须在 state.json 中硬编码
3. **每次写前必读 state.json** — 不读等于没写
4. **软约束 = 无约束** — 所有检查必须强制执行
