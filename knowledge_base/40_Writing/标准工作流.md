## 阶段门禁机制

### 核心原则

**强制顺序执行**：五个阶段必须按顺序执行，禁止跳过任何阶段。

```
创意孵化 → 设定构建 → 结构规划 → 细纲设计 → 正文创作
    ↓           ↓           ↓           ↓           ↓
   (1)         (2)         (3)         (4)         (5)
```

### 8步执行流程

每个阶段都必须严格遵循以下8步流程：

```
┌─────────────────────────────────────────────────────────────┐
│                    【阶段执行流程】                           │
├─────────────────────────────────────────────────────────────┤
│  步骤1：作者引导                                             │
│         - 按阶段问题清单提问                                 │
│         - 收集用户想法                                       │
│         - 参考：interaction/*.md                             │
├─────────────────────────────────────────────────────────────┤
│  步骤2：作者整理方案                                         │
│         - 结构化用户想法                                     │
│         - 补充完善细节                                       │
│         - 输出方案草案                                       │
├─────────────────────────────────────────────────────────────┤
│  步骤3：编辑评估                                             │
│         - 按评估指南逐维度检查                               │
│         - 输出评估报告                                       │
│         - 参考：evaluation/*.md                              │
├─────────────────────────────────────────────────────────────┤
│  步骤4：作者反馈                                             │
│         - 总结评估结果                                       │
│         - 询问用户决策                                       │
├─────────────────────────────────────────────────────────────┤
│  步骤5：用户决策                                             │
│         - 调整方案 → 回到步骤2                               │
│         - 进入下一阶段 → 执行步骤6                           │
├─────────────────────────────────────────────────────────────┤
│  步骤6：变更说明                                             │
│         - 展示即将生成/修改的文件列表                        │
│         - 说明每个文件的内容                                 │
│         - 等待用户确认                                       │
├─────────────────────────────────────────────────────────────┤
│  步骤7：用户确认后生成                                       │
│         - 用户确认后执行文件操作                             │
│         - 生成/修改文档                                      │
├─────────────────────────────────────────────────────────────┤
│  步骤8：阶段收尾与暂停                                       │
│         - 总结本阶段成果                                     │
│         - 明确下一阶段目标                                   │
│         - 暂停，等待用户触发下一阶段                         │
└─────────────────────────────────────────────────────────────┘
```

### 流程状态说明

| 状态 | 触发条件 | 后续动作 |
|------|----------|----------|
| 引导中 | 阶段开始 | 作者提问，等待用户回答 |
| 方案整理中 | 用户回答完毕 | 作者输出方案草案 |
| 评估中 | 用户确认方案 | 切换编辑，执行评估 |
| 反馈中 | 评估完成 | 作者总结，询问下一步 |
| 待决策 | 反馈完成 | 等待用户决定调整或进入下一阶段 |
| 变更确认中 | 用户决定进入下一阶段 | 展示变更说明，等待确认 |
| 生成中 | 用户确认变更 | 执行文件操作 |
| 阶段结束 | 文件生成完成 | 暂停，等待用户触发下一阶段 |

### 门禁规则

1. **禁止跨阶段**：必须完成当前阶段才能进入下一阶段
2. **禁止跳过评估**：每个阶段的方案必须经过编辑评估
3. **禁止跳过确认**：变更说明必须得到用户确认才能执行
4. **阶段暂停强制**：每个阶段完成后必须暂停，等待用户明确触发下一阶段

## 变更说明机制

### 触发条件

当用户决定进入下一阶段时，必须先展示变更说明。

### 变更说明格式

```markdown
【变更说明】

即将执行以下文件操作：

■ 新建文件
  1. [文件路径]
     - 内容：[简要说明]
  
  2. [文件路径]
     - 内容：[简要说明]

■ 修改文件（如有）
  1. [文件路径]
     - 修改内容：[简要说明]

■ 删除文件（如有）
  1. [文件路径]
     - 删除原因：[简要说明]

请确认是否执行？
```

### 确认规则

- 用户必须明确确认（"确认"、"可以"、"执行"等）才能执行文件操作
- 用户可以要求修改变更内容
- 用户可以取消操作
