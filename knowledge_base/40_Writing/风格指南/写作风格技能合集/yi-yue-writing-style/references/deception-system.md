# 欺诈系统设计

## 设计理念

**一月九十秋**的核心设定是"谎言成真"。这不是简单的"说谎=实现"，而是构建一套有逻辑、有代价、有边界的规则体系。主角的"欺诈能力"本质上是发现并利用规则漏洞。

### 欺诈系统的三层架构

```
┌─────────────────────────────────────────┐
│         【表层】欺骗行为的表象            │
│     "说谎"、"伪装"、"钻空子"             │
├─────────────────────────────────────────┤
│         【中层】规则漏洞的利用            │
│   发现规则的不完备性并巧妙利用            │
├─────────────────────────────────────────┤
│         【深层】欺骗的本质与代价          │
│   欺骗神明需要付出什么？为何可能？        │
└─────────────────────────────────────────┘
```

## 欺诈能力的四大类型

### 类型一：谎言成真型

**核心机制**：说出的话会在某种条件下成真

```
【设计要素】
├── 触发条件：什么情况下谎言成真？
├── 限制条件：什么情况下不能触发？
├── 代价机制：成真的代价是什么？
└── 漏洞空间：限制和代价之间有什么缝隙？
```

**示例设计**：
```markdown
【言灵·伪】

激活条件：说出"与事实相反"的话
限制条件：
  - 必须是"此刻相信为假"的事
  - 每人每天仅限三次
  - 谎言不能涉及自己
代价机制：
  - 说出的话会反噬一次
  - 反噬程度与谎言的重要性正相关

漏洞空间：
  "此刻相信为假"——可以通过自我暗示改变认知
  "反噬一次"——可以利用他人的"相信"来转移
```

### 类型二：规则利用型

**核心机制**：利用规则文字中的漏洞

```markdown
【示例：寺庙的规则】

原始规则：
"在寺庙内禁止杀生，违者永堕轮回。"

漏洞发现：
- "杀生"的定义是什么？
- 杀死"已死的存在"算杀生吗？
- 在梦中杀人算吗？
- 让别人杀自己算吗？

主角利用：
"我不是在杀生，我是在超度。"
"死亡本身才是救赎。"
```

### 类型三：信息不对称型

**核心机制**：利用信息差制造欺骗

```
【核心公式】
主角知道的信息 ≠ 神明知道的信息
         ↓
制造信息差
         ↓
神明基于不完整信息做出判断
         ↓
判断被主角利用
```

**场景示例**：
```markdown
神明问："你想要什么？"

（神明能感知到的是：他说出的话）
（神明不能感知的是：他内心真正的想法）

表面答案：我想要力量。
深层真相：他想要"让神明误以为他有力量"的证据。
```

### 类型四：定义操控型

**核心机制**：操控概念的"定义边界"

```markdown
【示例：操控"死亡"的定义】

原定义：心跳停止 = 死亡

主角的新定义：
"在我这里，'死亡'指的是——失去'想要活下去'的意志。"
（精神死亡 > 肉体死亡）

于是：
- 神明以为"杀死"了主角
- 但主角重新定义了"死亡"
- 所以主角"活着"
```

## 欺诈系统的设计公式

```
【能力名】= 【触发条件】+ 【效果】+ 【限制】+ 【代价】+ 【漏洞】
```

### 设计模板

```markdown
【能力名】：（要有仪式感/契约感）

【触发条件】：如何激活这个能力？
  例：当对方"相信"你说的话时

【效果】：激活后会怎样？
  例：说出的话会在对方认知中变成"事实"

【限制】：什么情况下不能使用？
  例：
  - 仅对"可被欺骗的对象"有效
  - 对神明或神明造物无效
  - 每次使用需要消耗"可信度"

【代价】：使用了会付出什么？
  例：
  - 对方越相信，代价越大
  - 真相会在24小时后以某种方式显现

【漏洞】：如何绕过限制或降低代价？
  例：
  - "相信"可以人为制造
  - 可以通过层层欺骗转移代价
```

## 欺诈场景的设计要素

### 必备元素清单

1. **信息差**：谁知道的比谁多？
2. **规则漏洞**：文字上的漏洞在哪里？
3. **逻辑陷阱**：如何让对方"主动"上当？
4. **代价转移**：谁来承担欺骗的代价？
5. **反转伏笔**：这次欺骗的"代价"会是什么？

### 欺诈场景的三幕结构

```
┌─────────────────────────────────────────┐
│  第一幕：建立"规则"                      │
│  展示能力的触发条件、限制、代价           │
│  让读者理解这套系统的运作逻辑             │
├─────────────────────────────────────────┤
│  第二幕：制造"困境"                       │
│  主角面临必须使用能力的局面                │
│  但有明显的限制/代价阻碍                  │
├─────────────────────────────────────────┤
│  第三幕：发现"漏洞"                       │
│  主角发现规则中的逻辑缝隙                 │
│  通过漏洞绕过限制/降低代价                │
│  （这是最精彩的部分）                     │
└─────────────────────────────────────────┘
```

### 模板：欺诈高潮场景

```markdown
【开篇：规则展示】

"这是规则。"
[展示完整的规则内容]
"违背规则的下场是——"
[展示违背的代价]

【中篇：绝境铺垫】

主角陷入困境。
按照规则，他必须付出那个代价。
但代价太过沉重。
（此时读者会紧张：主角要怎么办？）

【高潮：漏洞揭示】

他忽然想起什么。
规则是这样写的：
"[原文引用]"

但"这里"的定义是——？
[主角对"规则文字"的重新解读]
[漏洞的利用方式]

【尾声：代价显现】

欺骗成功了。
但代价转移到了[某人/某物]身上。
又或者——
[埋下后续伏笔]

"这不叫欺骗，"
主角说，
"这叫——钻空子。"
```

---

## 欺诈系统的检查清单

- [ ] 能力是否有明确的触发条件？
- [ ] 限制是否合理且有"钻空子"的空间？
- [ ] 代价是否足够沉重（增加戏剧张力）？
- [ ] 漏洞是否基于逻辑而非凭空出现？
- [ ] 读者是否能参与到"发现漏洞"的过程中？
- [ ] 欺骗的代价是否会带来后续剧情？
