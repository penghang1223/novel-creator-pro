## 二、闭环机制设计

### 2.1 总体架构

```
┌─────────────────────────────────────────────────────┐
│              写前 Pre-Write Check                    │
│  ① AI词黑名单预载                                    │
│  ② 标题关键词预注册                                   │
│  ③ 人物对话差异化档案                                 │
│  ④ 设定一致性预检                                     │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│              写中 In-Write Constraints               │
│  ⑤ 禁止使用黑名单词汇                                 │
│  ⑥ 对话比例实时监控(≥25%)                             │
│  ⑦ 每章必须有标题关键词                                │
│  ⑧ 场景描写不超300字无对话                            │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│              写后 Post-Write Audit                    │
│  ⑨ 自动统计AI词频次                                   │
│  ⑩ 对话比例计算                                       │
│  ⑪ 标题关键词验证                                     │
│  ⑫ 重复段落检测                                       │
│  ⑬ 生成审计报告，超标则自动修复                         │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│              定期 Review (每5章)                      │
│  ⑭ 全书AI词趋势分析                                    │
│  ⑮ 人物对话区分度测试                                  │
│  ⑯ 设定一致性检查                                     │
│  ⑰ 标题-内容匹配率                                    │
└─────────────────────────────────────────────────────┘
```

### 2.2 AI词黑名单（写前预载，写后审计）

**绝对禁止词**（写后必须为0）：
- `像是` — 目标 ≤1/20章

**严格限制词**（每20章总量控制）：

| 词汇 | 20章上限 | 单章上限 | 替代方案 |
|------|----------|----------|----------|
| 像(比喻) | ≤10 | ≤1 | 如同/如/直接描写 |
| 突然 | ≤5 | ≤1 | 一下子/忽地/冷不丁/猛然/骤然 |
| 微微 | ≤5 | ≤1 | 扬了扬/蹙了蹙/颤了颤/泛红/缩了一下 |
| 沉默 | ≤5 | ≤1 | 没说话/安静了X秒/顿了X秒 |
| 天旋地转 | ≤2 | 0 | 每次用不同写法 |
| 感觉 | ≤10 | ≤1 | 具体感官描写 |
| 嘴角 | ≤5 | ≤1 | 笑了/笑起来/唇边 |

**浓度红线**：
- 任何AI词单章出现 ≥3次 → 自动标记为"浓度超标"
- 全章AI词总数 ≥10 → 标记为"AI味过重"，必须润色

**副词"XX地"限制**（新增）：

副词结构"XX地"（如"缓缓地""静静地""仔细地"）≤2个/章。根因：AI默认偏好副词堆叠。替代方案：用动作本身传递节奏（"他放慢脚步"而非"他缓慢地走着"）。

### 2.2.1 AI式表达习惯（新增）

**根因**：AI追求"像文学"而非"像人"，模仿人类情感时用力过猛或理解偏差。人类文字更粗糙、具体、充满感官细节，而非光滑但空洞的塑料感。

**类别一：表情与神态僵尸化**

| 词汇/模式 | 限制 | 根因 | 替代方案 |
|-----------|------|------|----------|
| 嘴角（勾起/上扬/抽搐） | ≤1/章 | 人类笑是整张脸运动，非单独控制嘴角 | 笑了/眼里有了笑意/似笑非笑 |
| 邪魅（一笑/眼神） | 绝对禁止 | 古早言情小说遗留毒瘤，现代语境下油腻 | 直接写行为 |
| 抽搐（嘴角/眼皮） | 绝对禁止（非病理场景） | 除非病理，人类更多是"僵住/抿嘴/咬肌紧绷" | 僵住了/抿了抿嘴/咬肌紧绷 |

**类别二：对话标签说明书化**

| 词汇/模式 | 限制 | 根因 | 替代方案 |
|-----------|------|------|----------|
| 解释道/询问道/反问道 | 绝对禁止 | 把潜台词写死，像相声抖包袱前先解释"这里该笑了" | 直接用"说"/"问"，或用动作代替 |
| XX地喊道/冷冷地回答 | ≤1/章 | 对话写得好，读者自然能读出语气 | 动作代替："他一把推开我" |

**类别三：程度副词滥用**

| 词汇 | 限制 | 根因 | 替代方案 |
|------|------|------|----------|
| 一丝（笑意/悲伤/尴尬） | ≤1/章 | AI太爱用"一丝"表现细腻，过多则矫情 | 直接描写神态/用"点""点儿" |
| 异常/格外/分外 | ≤1/章 | 偷懒词，用来说明而非描写 | 写具体场景（"静得能听见灰尘落地"） |
| 猛地/立刻/瞬间 | ≤1/章 | 节奏太快，缺乏过程 | 描写动作起势，不直接给结果 |

**类别四：抽象名词空洞堆砌**

| 词汇/模式 | 限制 | 根因 | 替代方案 |
|-----------|------|------|----------|
| 气息（危险的/神秘的/强者的） | 绝对禁止 | 万金油词，掩盖描写能力不足 | 写具体味道/声音/光影 |
| 灵魂/深处（触动灵魂/记忆深处/灵魂深处战栗） | 绝对禁止 | 过于宏大叙事，缺乏落地感 | 用具体行为/细节替代 |

**类别五：逻辑连接词翻译腔**

| 词汇 | 限制 | 根因 | 替代方案 |
|------|------|------|----------|
| 然而 | 绝对禁止 | 太书面，中文口语/现代小说很少用 | 可是/但/不过 |
| 尽管…还是… | 绝对禁止 | 句式结构感太强，像翻译 | "累归累，他还是…"/"虽然…可是…" |
| 虽然…但是…（过度使用） | ≤2/章 | 结构感强 | 打散为自然句式 |

### 2.3 标题-正文匹配机制

**规则**：每章标题的关键词必须在正文中出现至少1次。

**执行流程**：
1. 生成章节标题时，提取标题中≥2字的核心词
2. 正文生成后，扫描检查核心词是否在正文中出现
3. 如果未出现 → 在正文中自然嵌入该词，或修改标题

### 2.2.2 AI式常识幻觉（新增）

**根因**：AI没有身体，不懂重力/温度/光线/空间在现实中的真实表现。写出来的东西"太像小说"却唯独不像人写的。

**总原则**：多用动词，少用形容词；多写生理反应，少写心理定义；多写具体物体，少写抽象概念。

#### 物理与感官幻觉

| 问题 | 典型错误 | 约束 | 正确写法 |
| --- | --- | --- | --- |
| 光线逻辑混乱 | "月光照亮了整个漆黑的房间" | 光源必须一致——无光不能有"泪光/看清" | "月光洒在床沿，勉强勾勒出桌子轮廓" |
| 声音无视距离 | 暴雨雷鸣中听到"轻微叹息" | 大噪音环境下不能写听到微小声 | 写动作/表情代替声音 |
| 温度体感缺失 | "端着滚烫茶杯紧紧握住" | 滚烫→松手/换手，不能紧握 | 写痛觉反射（烫得缩了一下） |

#### 动作鬼畜循环

| 问题 | 典型错误 | 约束 | 正确写法 |
| --- | --- | --- | --- |
| 莫名其妙歪头 | "歪了歪头，若有所思"（高频） | ≤1/章 | 皱眉/托腮/眼神放空/咬嘴唇 |
| 深呼吸滥用 | "深吸一口气，试图平复心情"（每段都用） | ≤1/章 | 紧张→屏住呼吸/呼吸急促 |
| 重复面部动作 | 揉眉心→按太阳穴→捏鼻梁循环 | 同一章不重复使用同一部位 | 换不同身体部位或写其他动作 |

#### 空间方位迷宫

| 问题 | 典型错误 | 约束 | 检查方法 |
| --- | --- | --- | --- |
| 门与位置瞬移 | 背靠门→走到窗边（无移动过程） | 跨房间/远距离移动必须有过程 | 每章检查人物位置是否连续 |
| 物品凭空消失/出现 | 手里拿剑→掏出手机（剑去哪了） | 手持物品状态必须维持 | 写前列出物理状态清单（见红线系统§6.5） |

#### 心理与反应过度理性

| 问题 | 典型错误 | 约束 | 正确写法 |
| --- | --- | --- | --- |
| 直接说出心理 | "自嘲地笑了笑：'我真是个傻瓜'" | 禁止角色直接说出自嘲台词 | 写无声苦笑/隐晦吐槽 |
| 情绪瞬间切换 | 愤怒吼叫→温柔看着（无冷却期） | 情绪切换必须有过渡（至少1段） | 写冷却过程（沉默/移开视线/深呼吸） |
| 直接命名情绪 | "空气中弥漫着尴尬的气氛" | 禁止直接命名情绪 | 写具体细节（"没人说话，只有空调嗡嗡声"） |

#### 翻译腔

| 问题 | 典型错误 | 约束 | 正确写法 |
| --- | --- | --- | --- |
| "是……的"结构 | "这是一个值得深思的问题" | ≤1/章 | "这问题值得深思" |
| 超长定语从句 | "那个穿着红裙子拿着气球的女孩" | 名词前定语≤2个 | 拆为短句："女孩走过来。穿着红裙子。" |

### 2.4 人物对话差异化机制

**规则**：每个重要角色必须有可辨识的说话风格。

**执行流程**：
1. 立项时为每个核心角色创建"对话风格档案"：
   - 说话节奏（短句/长句/混合）
   - 口头禅/常用词
   - 禁用词（如"嗯"占比≤20%）
2. 写作时参考档案
3. 写后审查：统计每个角色的台词中"嗯/啊/哦"等填充词占比

### 2.4.1 口语化指数（新增）

**规则**：对话不能像书面报告。真人说话的特点是不完整、有省略、会打断、会跑题。

**口语化检测维度**：

| 维度 | 真人特征 | AI典型问题 | 检查方法 |
|------|----------|------------|----------|
| 省略 | "知道了"而非"我已经知道了" | 每句话都完整 | 对话中省略主语/宾语的比例应≥30% |
| 打断/抢话 | 没等对方说完就插话 | 每段对话都是完整的问答 | 每章至少1次打断场景 |
| 语气词 | "嗯"、"啊"、"吧"、"呢" | 几乎没有或过多 | 控制在≤20%（填充词占比） |
| 跑题 | 说着一件事突然想到另一件 | 每句话都紧扣主题 | 允许适度跑题，但需服务于人物塑造 |
| 身份差异 | 不同身份用词不同 | 所有人都用同一种书面语 | 对比角色对话的词汇选择 |

**写后抽查清单**（每章抽取3段对话）：

1. 这段对话有没有至少一个口语化特征（省略/打断/语气词）？
2. 遮住说话人名字，能猜出是谁说的吗？
3. 这段对话是否承载了有效信息（而非水字数）？

**违规判定**：

- 连续3段对话都是完整的"主谓宾"结构 → 口语化不达标
- 遮住说话人名字后无法区分角色 → 对话风格同质化
- 一段对话超过100字但没有推动剧情/关系 → 水字数

### 2.5 描写-对话比例机制

**规则**：网文对话比例≥25%。

**执行流程**：
1. 写作时有意控制：每300字至少有1段对话
2. 写后统计：对话字数/总字数
3. 如果<25% → 增加角色互动和对话

### 2.6 重复检测机制

**规则**：相邻章节重复度≤20%。

**执行流程**：
1. 生成新章前，读取上一章全文
2. 检测新章开头200字与上一章开头200字的相似度
3. 如果重复度>20% → 重写开头

### 2.7 桥段去重库（新增）

**规则**：每章提取 3 个核心桥段标签，写入 novel_state.json 的 bridge_archive。写新章前比对最近 5 章，禁止使用相同标签。

**桥段标签分类**：

| 类别 | 示例标签 |
|------|----------|
| 场景模式 | 深夜失眠、快餐店偶遇、茶水间对话、办公室夜景 |
| 互动模式 | 手机对话、上门敲门、群聊进度 |
| 内心模式 | 数学计算、内心独白、回忆闪回 |
| 发现模式 | 数据发现、窗外观察、意外线索 |

**执行流程**：
1. 每章写完审计通过后，提取 3 个桥段标签写入 novel_state.json
2. 写新章前读取最近 5 章的桥段标签
3. 如果计划使用的桥段已在最近 5 章用过 → 换一个
4. 同一桥段标签至少间隔 5 章才能重复使用

### 2.8 节奏仪表盘（新增）

**规则**：每章标注节奏类型（推进/铺垫/高潮/过渡），写入 novel_state.json 的 rhythm_dashboard。

**节奏类型定义**：

| 类型 | 含义 | 信息密度 | 张力范围 |
|------|------|----------|----------|
| 推进 | 主线有新事件发生 | 高 | 5-7 |
| 铺垫 | 为后续事件做准备 | 中 | 3-5 |
| 高潮 | 冲突爆发/重大转折 | 最高 | 8-10 |
| 过渡 | 事件之间的缓冲 | 低 | 1-3 |

**预警规则**：
- 连续 3 章同类型 → 黄色警告（建议调整下一章类型）
- 连续 5 章同类型 → 红色警告（必须调整下一章类型）
- 连续 3 章张力≤3 → 红色警告（节奏太平，需要冲突升级）
- 连续 3 章张力≥8 → 黄色警告（读者疲劳，需要缓冲）

**健康模式**：铺垫→推进→高潮→过渡→推进→铺垫（波浪式起伏）

## 三、写后审计脚本

每章生成后，**必须**运行以下审计流程：

```python
# 伪代码：post_write_audit(chapter_text, prev_chapter_text, title)
audit_results = {
    "ai_words": count_ai_words(chapter_text),      # 各AI词频次
    "dialogue_ratio": calc_dialogue_ratio(chapter_text),  # 对话%
    "title_keyword_match": check_title_keywords(chapter_text, title),  # 标题关键词
    "repeat_check": check_repeat(chapter_text, prev_chapter_text),  # 重复度
    "word_count": len(chapter_text),               # 字数
    "pass": all_checks_passed,                     # 是否全部通过
}
```

**如果任何检查不通过**：
- 自动修复（AI词替换、增加对话、嵌入关键词）
- 输出修复报告
- 用户确认后再输出最终版

## 四、定期复盘机制（每5章）

每完成5章，执行一次全书级别的审计：

1. **AI词趋势**：统计全书各词总量和趋势（上升/下降）
2. **人物对话区分度**：统计每个角色的填充词占比
3. **设定一致性**：检查货币体系、修炼体系等是否前后统一
4. **标题匹配率**：所有章节标题关键词是否都在正文中出现
5. **重复章节对**：检测任意两章的重复度

审计报告写入 `novel_state.json` 的 `audit_history`。

### 4.1 套路化趋势分析（新增）

每5章定期复盘时，增加一项：

- **套路化检测**：
  - 统计最近5章中使用了哪些套路库中的模式
  - 评估每个套路是否有绕开
  - 如果超过60%的章节使用了套路且未绕开 → 标记"套路化严重"
  - 输出绕开建议

## 五、教训转化为规则

| 教训 | 转化规则 |
|------|----------|
| ch1开头平淡 | 写前检查：前300字必须有冲突/悬念/动作 |
| ch2/ch3重复90% | 写前读取上一章，禁止开头200字重复>20% |

## 八、写后自我进化（每章触发）

### 8.1 核心理念

写完一章不是终点。**每章都是下一章的训练数据。**

完结复盘是"大考总结"，写后自我进化是"每课作业订正"。后者比前者重要——因为错误在连载初期就能被修正，而不是写到200章才发现问题。

### 8.2 触发时机

每章正文交付给用户**之后**，根据用户反馈自动触发。不需要用户说"反思一下"。

### 8.3 执行流程

```
章节交付
    │
    ▼
┌─────────────────────────────────────────┐
│  ① 用户反馈收集                           │
│  · 用户表扬了哪段？ → 记录"好写法"        │
│  · 用户批评了哪段？ → 记录"坏写法"        │
│  · 用户修改了哪段？ → 对比差异            │
│  · 用户没说话直接过？ → 默认通过          │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│  ② 自我审计                              │
│  · 对照红线：有没有触犯？                 │
│  · 对照常识：有没有编术语/法条/数值？     │
│  · 对照人味：有没有表演式情绪/完美对话？  │
│  · 照AI痕迹：有没有模板化/排比滥用？      │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐

│  · 新出现的AI词 → 加入限制词表           │
│  · 重复犯的错误 → 升级红线描述           │
│  · 用户新给的约束 → 写入反馈记忆          │
│  · 写得好的段落 → 提取为模板/示例        │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│  ④ 下一章生效                            │
│  · 新增约束写入 novel_state.json         │
```

### 8.6 完结复盘与写后进化的区别

| 维度 | 写后自我进化（每章） | 完结复盘（全书） |
| ---- | -------------------- | ---------------- |

| 关注范围 | 本章具体问题 | 全书统计趋势 |
| 更新速度 | 立即生效，下一章受益 | 下一本小说受益 |
| 数据来源 | 用户反馈 + 自我审计 | 全书所有章节数据 |
| 规则置信度 | 高（用户直接反馈） | 中（统计分析推断） |

**两者互补，不可替代。** 写后进化解决"这一章哪里错了"，完结复盘解决"整本书有哪些系统性问题"。

## 七、完结复盘升级机制

### 7.1 触发条件

当一本小说**完结**（最后一章写完或用户说"完结了"）时，自动触发复盘升级。

### 7.2 复盘流程

```
小说完结
    │
    ▼
┌─────────────────────────────────────────┐
│  ① 数据收集                              │
│  · 扫描所有章节正文                       │
│  · 扫描所有审查报告(审查/评估/一致性)      │
│  · 加载 novel_state.json (revision等)    │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│  ② 问题分析                              │
│  · 统计AI词全书使用模式                   │
│  · 提取报告中的P0/P1/P2问题              │
│  · 检测模板化描写模式                     │
│  · 统计超标章节数和严重程度               │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│  ③ 新规则识别                            │
│  · 对比现有红线系统，找出未覆盖的问题      │
│  · 按置信度排序新规则(高/中/低)           │
│  · 分类：AI限制词/质量规则/模板警告/关注词 │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│  ④ 规则写入                              │
│  · AI限制词 → 闭环质量控制.md §2.2       │

                     ▼
┌─────────────────────────────────────────┐

```

### 7.3 执行脚本

```bash

    --novel-dir "novel_output/{平台}/{小说名}/"

# 输出报告
python novel_creation_promax/scripts/novel_review_and_upgrade.py \
    --novel-dir "novel_output/{平台}/{小说名}/" --output review_report.md
```
