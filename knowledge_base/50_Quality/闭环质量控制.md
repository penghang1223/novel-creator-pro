## 二、闭环机制设计

### 2.1 总体架构

```
┌─────────────────────────────────────────────────────┐
│              写前 Pre-Write Check                    │
│  ① AI词黑名单预载                                    │
│  ② 标题关键词预注册                                   │
│  ③ 人物对话差异化档案                                 │
│  ④ 设定一致性预检                                     │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│              写中 In-Write Constraints               │
│  ⑤ 禁止使用黑名单词汇                                 │
│  ⑥ 对话比例实时监控(≥25%)                             │
│  ⑦ 每章必须有标题关键词                                │
│  ⑧ 场景描写不超300字无对话                            │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│              写后 Post-Write Audit                    │
│  ⑨ 自动统计AI词频次                                   │
│  ⑩ 对话比例计算                                       │
│  ⑪ 标题关键词验证                                     │
│  ⑫ 重复段落检测                                       │
│  ⑬ 生成审计报告，超标则自动修复                         │
└──────────────────────┬──────────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────────┐
│              定期 Review (每5章)                      │
│  ⑭ 全书AI词趋势分析                                    │
│  ⑮ 人物对话区分度测试                                  │
│  ⑯ 设定一致性检查                                     │
│  ⑰ 标题-内容匹配率                                    │
└─────────────────────────────────────────────────────┘
```

### 2.2 AI词黑名单（写前预载，写后审计）

**绝对禁止词**（写后必须为0）：
- `像是` — 目标 ≤1/20章

**严格限制词**（每20章总量控制）：

| 词汇 | 20章上限 | 单章上限 | 替代方案 |
|------|----------|----------|----------|
| 像(比喻) | ≤10 | ≤1 | 如同/如/直接描写 |
| 突然 | ≤5 | ≤1 | 一下子/忽地/冷不丁/猛然/骤然 |
| 微微 | ≤5 | ≤1 | 扬了扬/蹙了蹙/颤了颤/泛红/缩了一下 |
| 沉默 | ≤5 | ≤1 | 没说话/安静了X秒/顿了X秒 |
| 天旋地转 | ≤2 | 0 | 每次用不同写法 |
| 感觉 | ≤10 | ≤1 | 具体感官描写 |
| 嘴角 | ≤5 | ≤1 | 笑了/笑起来/唇边 |

**浓度红线**：
- 任何AI词单章出现 ≥3次 → 自动标记为"浓度超标"
- 全章AI词总数 ≥10 → 标记为"AI味过重"，必须润色

### 2.3 标题-正文匹配机制

**规则**：每章标题的关键词必须在正文中出现至少1次。

**执行流程**：
1. 生成章节标题时，提取标题中≥2字的核心词
2. 正文生成后，扫描检查核心词是否在正文中出现
3. 如果未出现 → 在正文中自然嵌入该词，或修改标题

### 2.4 人物对话差异化机制

**规则**：每个重要角色必须有可辨识的说话风格。

**执行流程**：
1. 立项时为每个核心角色创建"对话风格档案"：
   - 说话节奏（短句/长句/混合）
   - 口头禅/常用词
   - 禁用词（如"嗯"占比≤20%）
2. 写作时参考档案
3. 写后审查：统计每个角色的台词中"嗯/啊/哦"等填充词占比

### 2.5 描写-对话比例机制

**规则**：网文对话比例≥25%。

**执行流程**：
1. 写作时有意控制：每300字至少有1段对话
2. 写后统计：对话字数/总字数
3. 如果<25% → 增加角色互动和对话

### 2.6 重复检测机制

**规则**：相邻章节重复度≤20%。

**执行流程**：
1. 生成新章前，读取上一章全文
2. 检测新章开头200字与上一章开头200字的相似度
3. 如果重复度>20% → 重写开头

## 三、写后审计脚本

每章生成后，**必须**运行以下审计流程：

```python
# 伪代码：post_write_audit(chapter_text, prev_chapter_text, title)
audit_results = {
    "ai_words": count_ai_words(chapter_text),      # 各AI词频次
    "dialogue_ratio": calc_dialogue_ratio(chapter_text),  # 对话%
    "title_keyword_match": check_title_keywords(chapter_text, title),  # 标题关键词
    "repeat_check": check_repeat(chapter_text, prev_chapter_text),  # 重复度
    "word_count": len(chapter_text),               # 字数
    "pass": all_checks_passed,                     # 是否全部通过
}
```

**如果任何检查不通过**：
- 自动修复（AI词替换、增加对话、嵌入关键词）
- 输出修复报告
- 用户确认后再输出最终版

## 四、定期复盘机制（每5章）

每完成5章，执行一次全书级别的审计：

1. **AI词趋势**：统计全书各词总量和趋势（上升/下降）
2. **人物对话区分度**：统计每个角色的填充词占比
3. **设定一致性**：检查货币体系、修炼体系等是否前后统一
4. **标题匹配率**：所有章节标题关键词是否都在正文中出现
5. **重复章节对**：检测任意两章的重复度

审计报告写入 `novel_state.json` 的 `audit_history`。

## 五、教训转化为规则

| 教训 | 转化规则 |
|------|----------|
| ch1开头平淡 | 写前检查：前300字必须有冲突/悬念/动作 |
| ch2/ch3重复90% | 写前读取上一章，禁止开头200字重复>20% |
| "像是"128次 | 加入黑名单，写后审计必须=0 |
| "像"比喻212次 | 严格限制词，20章≤10 |
| ch4对话12% | 对话比例<25%必须修复 |
| 谢无妄80%="嗯" | 人物对话档案：填充词占比≤20% |
| 货币体系不一致 | 设定必须在正文中明确说明，写后检查 |
| 标题14个不匹配 | 标题关键词必须在正文出现，写后验证 |
| "突然/沉默/微微"各30+ | 加入严格限制词表，写后审计 |
| "天旋地转"7次 | 场景描写必须多样化，禁止模板化 |

## 六、执行清单

每次写章前，确认以下清单：

- [ ] AI词黑名单已加载到上下文
- [ ] 上一章已读取（防止重复）
- [ ] 人物对话档案已加载
- [ ] 标题关键词已提取
- [ ] 设定一致性检查清单已准备

每次写章后，确认以下清单：

- [ ] AI词频次统计通过
- [ ] 对话比例≥25%
- [ ] 标题关键词在正文中出现
- [ ] 与上一章重复度≤20%
- [ ] 审计报告已生成

## 七、完结复盘升级机制

### 7.1 触发条件

当一本小说**完结**（最后一章写完或用户说"完结了"）时，自动触发复盘升级。

### 7.2 复盘流程

```
小说完结
    │
    ▼
┌─────────────────────────────────────────┐
│  ① 数据收集                              │
│  · 扫描所有章节正文                       │
│  · 扫描所有审查报告(审查/评估/一致性)      │
│  · 加载 novel_state.json (revision等)    │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│  ② 问题分析                              │
│  · 统计AI词全书使用模式                   │
│  · 提取报告中的P0/P1/P2问题              │
│  · 检测模板化描写模式                     │
│  · 统计超标章节数和严重程度               │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│  ③ 新规则识别                            │
│  · 对比现有红线系统，找出未覆盖的问题      │
│  · 按置信度排序新规则(高/中/低)           │
│  · 分类：AI限制词/质量规则/模板警告/关注词 │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│  ④ 规则写入                              │
│  · AI限制词 → 闭环质量控制.md §2.2       │
│  · AI限制词 → 红线系统.md §14           │
│  · 质量规则 → 闭环质量控制.md §五        │
│  · 模板警告 → 降低AI痕迹.md              │
│  · 关注词 → watch_words.md              │
└────────────────────┬────────────────────┘
                     ▼
┌─────────────────────────────────────────┐
│  ⑤ 下一本受益                            │
│  · 新小说自动加载更新后的规则              │
│  · 写前检查包含新增的AI限制词             │
│  · 写后审计检查新增的质量规则             │
└─────────────────────────────────────────┘
```

### 7.3 执行脚本

```bash
# 预览模式（查看报告但不写入）
python novel_creation_promax/scripts/novel_review_and_upgrade.py \
    --novel-dir "novel_output/{平台}/{小说名}/"

# 自动升级模式（写入知识库）
python novel_creation_promax/scripts/novel_review_and_upgrade.py \
    --novel-dir "novel_output/{平台}/{小说名}/" --upgrade

# 输出报告
python novel_creation_promax/scripts/novel_review_and_upgrade.py \
    --novel-dir "novel_output/{平台}/{小说名}/" --output review_report.md
```

### 7.4 规则置信度阈值

| 置信度 | 图标 | 含义 | 处理 |
|--------|------|------|------|
| ≥80% | ✅ | 明确问题，强烈建议升级 | 自动写入知识库 |
| 60%-80% | ⚠️ | 可能问题，建议关注 | 写入后人工审核 |
| <60% | 💡 | 弱信号，仅供参考 | 仅报告，不写入 |
