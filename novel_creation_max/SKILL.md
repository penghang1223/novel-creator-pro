# 小说创作 Max (旗舰版)

## 概览

这是小说创作的**旗舰级系统**，不是简单的文本生成器。它整合了四大核心模块：

1. **AI记忆中台**：生产级记忆系统，确保长篇创作的连贯性、一致性和稳定性
2. **多风格创作引擎**：覆盖爆款爽文、人性写作、毒舌神回复、专业叙事等全风格谱系
3. **智能工作流**：从立项到连载、从大纲到正文、从改编到校准的全流程自动化
4. **质量约束系统**：红线系统、必答问题、强制读取验证，确保创作质量与一致性

## 🚨 核心约束系统（v2.1新增）

### 三大质量保障机制

**机制1：红线系统（创作红线.md）**
- 一级红线（绝对禁止）：原创性、人称使用、性别姓名
- 二级红线（质量约束）：风格漂移、人物OOC、剧情矛盾、伏笔丢失
- 三级红线（质量优化）：章节推进、字数规范、结构规范、悬念机制
- 触发场景：所有创作类型，实时检测
- 处理流程：一级红线强制停止创作，二级/三级红线提供修正建议

**机制2：必答问题系统（章节创作前必答问题.md）**
- 触发场景：长篇第1章创作、长篇第2章及以后续写
- 核心问题：9个关键问题（章节位置、情节团、悬念承接、伏笔处理、人物关系、情绪爽点、核心推进事件、状态变化）
- 验证标准：必须用1句话清晰描述核心推进事件，主角状态至少有一项实质性变化
- 评分系统：满分90分，80-90分优秀，70-79分良好，60-69分合格，60分以下必须重新回答

**机制3：记忆系统输出格式（记忆系统输出格式.md）**
- 章节前记忆唤醒：输出唤醒确认，包含大纲、追踪、章节文件的读取证明
- 章节后记忆回填：输出回填确认，包含摘要、人物状态、伏笔状态、剧情进展、未解决问题
- 风格校准：输出校准报告，包含风格DNA、偏离度、修正建议
- 人物一致性检查：输出检查报告，包含人物档案、一致性分数、OOC风险、修正建议

### 约束系统的执行流程

**长篇章节创作完整流程**：

```
章节创作前必答问题（9个）→ 记忆系统唤醒（输出确认）→ 创作执行
→ 红线系统实时检测（一级强制停止，二级/三级修正建议）
→ 章节完成 → 记忆回填（输出确认）→ 风格校准（可选）
→ 人物一致性检查（可选）→ 输出章节质量报告
```

**约束优先级**：
1. 一级红线 > 必答问题 > 记忆唤醒 > 创作执行
2. 红线检测（实时）> 必答问题验证（创作前）> 记忆回填（创作后）
3. 质量修正 > 继续创作 > 交付结果

## 核心优势

与普通写作工具不同，本系统专注于：

- **长篇连载稳定性**：风格不跑偏、人物不OOC、剧情不打架、伏笔不丢
- **多风格适配**：支持主流网文、传统文学、AI漫剧、毒舌吐槽等多种风格
- **人性写作**：基于心理学和行为学的人设构建，让角色有温度、有血肉
- **智能记忆**：章节前自动唤醒、章节后自动回填、阶段性回顾压缩
- **防漂移机制**：风格DNA锁定、人物一致性检查、剧情逻辑校验

## 适用场景

- **长篇连载创作**：需要长期维护人物设定、剧情走向、风格统一的网文
- **短篇爆款写作**：需要快速生产符合平台算法的热门内容
- **AI漫剧改编**：将小说改编为AI漫剧的分镜和脚本
- **多题材融合**：将不同题材进行创新性融合和重构
- **风格迁移**：在保持故事内核的前提下改变写作风格
- **毒舌/神回复**：创作带有独特视角和犀利观点的内容

## 小说创作核心流程

### 流程一：长篇连载创作（旗舰级工作流）

#### 阶段1：项目立项与基础构建

**步骤1.1：确定核心要素**
```
题材选择 → 风格定位 → 核心冲突 → 目标读者 → 平台适配
```

- **题材选择**：参考 `references/风格指南/topic-library.md` 和 `references/风格指南/genre-fusion-guide.md`
  - 确定主题材（如：都市、玄幻、悬疑、言情）
  - 选择融合元素（如：都市+重生、玄幻+系统、悬疑+无限流）
  - 评估市场热度和竞争空间

- **风格定位**：参考 `references/风格指南/style-guide.md`
  - 选择主风格（如：当年明月、猫腻、金庸、古龙、孔二狗）
  - 确定辅助风格元素（如：毒舌吐槽、神回复、人性化描写）
  - 明确风格禁忌和混用限制

- **核心冲突**：参考 `references/技术基础/drama-storytelling.md`
  - 确定主线冲突（人物 vs 自我/环境/他人）
  - 设计支线冲突网络
  - 规划冲突的螺旋式上升路径

**步骤1.2：人物档案创建**
```
主角设计 → 配角构建 → 反派塑造 → 关系网络 → 成长弧线
```

- **使用模板**：参考 `references/模板工具/character-archetypes-2025.md`
  - 选择合适的人设原型（如：战神归来、废柴逆袭、天才陨落）
  - 填写核心人物档案（姓名、年龄、外貌、性格、背景、动机）
  - 设计人物的语言风格和行为模式

- **建立关系网络**
  - 明确人物之间的权力关系、情感关系、利益关系
  - 设计关系变化的触发点和轨迹
  - 预设关键冲突节点

- **规划成长弧线**
  - 确定初始状态、关键转折、终极目标
  - 设计成长的内在驱动力
  - 规划成长的外在表现

**步骤1.3：世界观构建**
```
核心规则 → 力量体系 → 社会结构 → 地理设定 → 历史背景
```

- **核心规则**：确定世界运行的基本法则
- **力量体系**：如武功、异能、科技、魔法等
- **社会结构**：阶级、组织、势力分布
- **地理设定**：主要场景、地标、环境特点
- **历史背景**：世界的前史、重大事件、遗留问题

#### 阶段2：记忆系统初始化

**步骤2.1：记忆系统初始化**
```bash
# 初始化记忆系统
python scripts/memory_manager.py init --memory-dir ./my_novel
```

- 创建记忆目录结构
- 建立五层记忆架构（风格DNA、人物、剧情、上下文、历史）
- 初始化记忆数据库

**步骤2.2：风格DNA提取（可选但推荐）**
```bash
# 如果有参考样本，提取风格DNA
python scripts/style_dna_extractor.py --input sample.txt --output style_dna.json
```

- **适用情况**：
  - 有优秀的参考作品（如名家名篇、个人满意的前作）
  - 需要严格保持风格一致性
  - 风格特征复杂难以人工描述

- **提取内容**：
  - 词汇特征：高频词、用词偏好、特色表达
  - 句式特征：长短句比例、句式结构、修辞手法
  - 节奏特征：段落节奏、对话节奏、叙事节奏
  - 情感特征：情感基调、情感强度、情感转换
  - 叙述特征：视角选择、叙述方式、信息密度

#### 阶段3：大纲与结构设计

**步骤3.1：总体大纲设计**
```
总章节规划 → 分卷设计 → 核心情节点 → 伏笔布局 → 节奏规划
```

- **参考文档**：`references/技术基础/technical-details.md`

- **总章节规划**
  - 确定总章节数和预计篇幅
  - 分配章节到不同的剧情阶段
  - 预留灵活调整空间

- **分卷设计**
  - 每卷的核心冲突和目标
  - 每卷的关键转折和成长
  - 卷与卷之间的衔接

- **核心情节点**
  - 开篇钩子（第1-3章）
  - 第一个高潮（第10-20章）
  - 中期转折（第50-60章）
  - 最终高潮（倒数10-20章）

- **伏笔布局**
  - 规划重要伏笔的植入点和回收点
  - 确保伏笔有足够的铺垫
  - 设计伏笔的揭示方式

**步骤3.2：章节细化**
```
每章目标 → 冲突设计 → 人物出场 → 场景安排 → 节奏控制
```

- **使用模板**：`references/模板工具/short-story-template.md`

- **每章目标**
  - 明确本章要推进的剧情线
  - 设计本章的核心冲突
  - 规划人物的成长或变化

- **冲突设计**
  - 参考 `references/技术基础/drama-storytelling.md` 中的导演设计原则
  - 应用三问原则：目标→行动→难题
  - 考虑双重身份和两打一下（如适用）

- **节奏控制**
  - 铺垫→冲突→高潮→回落
  - 张弛有度，避免持续高强度或过度平淡

#### 阶段4：章节创作（核心循环）

**步骤4.1：章节前记忆唤醒**
```bash
# 生成章节记忆包
python scripts/memory_manager.py chapter-pack --chapter 12 --output chapter_12_pack.json
```

- **记忆包内容**：
  - **active_characters**：当前活跃角色的最新状态
  - **active_plots**：进行中的剧情线和最近进展
  - **style_guardrails**：风格DNA特征和校准基准
  - **must_remember**：
    - 最近章节的摘要
    - 未解决的问题和疑问
    - 未回收的伏笔
  - **recent_history**：最近章节的关键事件和创作决策

- **使用建议**：
  - 创作前详细阅读记忆包
  - 特别关注未解决的问题和伏笔
  - 确保人物状态和性格一致
  - 保持语言风格符合DNA特征

**步骤4.2：章节创作执行**

```
开场钩子 → 场景铺垫 → 冲突展开 → 高潮推进 → 悬念收尾
```

- **开场钩子**
  - 参考 `references/模板工具/opening-hooks.md`
  - 每章开头都要有吸引力
  - 可以使用不同的钩子类型（如：悬念、情感、危机、反转）

- **场景铺垫**
  - 建立场景的时间和地点
  - 确定出场人物和他们的状态
  - 营造合适的氛围和节奏

- **冲突展开**
  - 应用三问原则循环1-2次
  - 每次冲突都要推动剧情或人物成长
  - 确保冲突有内在逻辑和情感基础

- **高潮推进**
  - 设计本章的情感或剧情高潮
  - 可以是冲突的解决、人物的重大变化、伏笔的揭示
  - 确保高潮有足够的情感冲击力

- **悬念收尾**
  - 为下一章埋下钩子
  - 可以是未解决的问题、新的威胁、人物的状态变化
  - 保持读者追读的欲望

- **风格控制**
  - 参考 `references/风格指南/style-guide.md` 和 `references/风格指南/witty-style-guide.md`
  - 保持语言风格的一致性
  - 应用特色风格元素（如毒舌、神回复、人性化描写）

**步骤4.3：风格校准（可选）**
```bash
# 章节完成后检查风格漂移
python scripts/style_calibrator.py --input chapter_12.txt --reference style_dna.json
```

- **适用情况**：
  - 觉得本章风格与之前有差异
  - 需要严格保持风格一致性
  - 创作过程中风格有所偏离

- **校准内容**：
  - 检查词汇使用是否符合DNA特征
  - 检查句式和节奏是否一致
  - 识别漂移的部分并建议修改

**步骤4.4：人物一致性检查（可选）**
```bash
# 检查人物是否OOC
python scripts/character_consistency_checker.py --input chapter_12.txt --character 主角名
```

- **适用情况**：
  - 觉得人物行为可能不符合设定
  - 人物有重大行为变化
  - 需要验证人物成长逻辑

- **检查内容**：
  - 行为是否符合人物的性格和动机
  - 对话是否符合人物的语言风格
  - 状态变化是否合理

#### 阶段5：章节后记忆回填

**步骤5.1：生成章节摘要**
```
总结内容 → 提取关键信息 → 标记人物状态 → 记录剧情进展 → 标记伏笔与问题
```

- **章节摘要结构**（参考 `references/记忆系统/chapter_sync_schema.md`）：
```json
{
  "chapter": 12,
  "title": "章节标题",
  "summary": "本章内容摘要",
  "key_elements": [
    "关键元素1",
    "关键元素2"
  ],
  "characters_involved": ["主角名", "配角名"],
  "character_states": [
    {
      "name": "主角名",
      "state": "当前状态描述",
      "change": "与上章相比的变化",
      "emotion": "情感状态"
    }
  ],
  "key_events": [
    {
      "event": "事件描述",
      "impact": "影响分析"
    }
  ],
  "plot_updates": [
    {
      "plot_name": "主线剧情",
      "event": "发生的事件",
      "status": "进行中",
      "impact": "对剧情的影响"
    }
  ],
  "foreshadowing_planted": ["伏笔1", "伏笔2"],

  "creative_decisions": [
    {
      "decision": "创作决策",

    }

```

**步骤5.2：回填记忆系统**
```bash
# 同步章节摘要到记忆系统
python scripts/memory_manager.py sync-chapter --input chapter_12_summary.json
```

- **同步内容**：
  - 创建新的上下文记忆（context）
  - 创建新的历史记录（history）
  - 更新相关人物的状态（character）
  - 更新相关剧情的进展（plot）
  - 标记和回收伏笔

- **注意事项**：
  - 摘要要准确反映本章内容
  - 人物状态要具体，便于后续唤醒
  - 剧情进展要清晰，便于追踪
  - 伏笔要详细描述，便于回收

#### 阶段6：阶段性回顾与优化

**步骤6.1：阶段性回顾**
```bash
# 每5-10章生成一次回顾报告
python scripts/memory_manager.py review-pack --chapter 50 --output review_50.json
```

- **回顾内容**：
  - **active_window**：当前活跃的角色、剧情、问题
  - **drift_risks**：潜在的风格漂移、人物漂移、剧情漂移
  - **archive_candidates**：可以归档的旧记忆
  - **recommended_actions**：优化建议

- **检查重点**：
  - 长期未推进的剧情线（超过6章）
  - 长期未刷新的角色（超过8章）
  - 风格漂移程度
  - 人物OOC事件
  - 未回收的伏笔
  - 记忆容量和性能

**步骤6.2：记忆优化**
```
归档旧记忆 → 压缩历史记录 → 清理冗余信息 → 验证一致性
```

- **归档旧记忆**
  - 将超过8-10章的上下文归档
  - 将已解决的剧情节点压缩成摘要
  - 保留未解决的伏笔和问题

- **压缩历史记录**
  - 将多个章节的历史记录压缩为阶段摘要
  - 保留关键事件和决策
  - 删除细节性信息

- **清理冗余信息**
  - 删除重复或冗余的人物状态
  - 删除不再活跃的角色详情
  - 删除已完成的剧情线详情

**步骤6.3：质量检查与修正**
```
一致性检查 → 逻辑验证 → 风格校准 → 内容优化
```

- **一致性检查**
  - 使用 `character_consistency_checker.py` 检查人物OOC
  - 检查人物成长轨迹是否合理
  - 检查人物关系变化是否自然

- **逻辑验证**
  - 检查剧情因果关系是否清晰
  - 检查伏笔和回收是否对应
  - 检查世界观设定是否自洽

- **风格校准**
  - 使用 `style_calibrator.py` 检查风格漂移
  - 对漂移的部分进行修正
  - 保持风格DNA的一致性

### 流程二：短篇爆款创作（快速工作流）

#### 阶段1：快速选题与定位

**步骤1.1：选题方向**
```
热点追踪 → 题材选择 → 目标读者 → 平台适配
```

- **热点追踪**
  - 参考各大平台的热榜和趋势
  - 关注当前热门话题和讨论
  - 分析近期爆款作品的特点

- **题材选择**
  - 参考 `references/风格指南/topic-library.md`
  - 选择热门题材或创新题材
  - 考虑题材的爆款潜力

- **目标读者**
  - 明确目标读者群体
  - 分析读者的痛点和爽点
  - 针对读者偏好设计内容

- **平台适配**
  - 了解平台的内容特点和算法
  - 针对平台优化标题、封面、节奏
  - 符合平台的内容规范

**步骤1.2：风格选择**
```
主风格选择 → 辅助风格 → 语言调性 → 爆款元素
```

- **主风格选择**
  - 参考 `references/风格指南/style-guide.md`
  - 选择最适合题材和读者的风格
  - 确保风格有爆款潜力

- **辅助风格**
  - 考虑融入毒舌、神回复等特色风格
  - 增强内容的独特性和传播性
  - 注意风格混用的禁忌

- **语言调性**
  - 确定语言风格（如：严肃、轻松、犀利、温暖）
  - 确定情感基调（如：爽感、感动、刺激、治愈）
  - 确保语言风格与内容和读者匹配

#### 阶段2：快速结构设计

**步骤2.1：选择结构模板**
```
模板选择 → 核心冲突设计 → 高潮规划 → 反转布局
```

- **模板选择**
  - 参考 `references/模板工具/short-story-template.md`
  - 选择适合题材和风格的结构模板
  - 根据需要调整模板结构

- **核心冲突设计**
  - 设计强冲突的矛盾对立体
  - 确保冲突有足够的情感张力
  - 应用三问原则：目标→行动→难题

- **高潮规划**
  - 设计情感冲击力强的高潮
  - 确保高潮有足够的铺垫
  - 设计高潮的爆发方式和结果

- **反转布局**
  - 设计1-2个意想不到的反转
  - 确保反转在预期之外又在情理之中
  - 用反转强化主题或爽感

**步骤2.2：开场钩子设计**
```
钩子选择 → 悬念设置 → 情感铺垫 → 节奏把控
```

- **钩子选择**
  - 参考 `references/模板工具/opening-hooks.md`
  - 选择适合题材的钩子类型
  - 确保钩子在前100字内出现

- **悬念设置**
  - 抛出核心悬念
  - 制造信息不对称
  - 激发读者的好奇心

- **情感铺垫**
  - 快速建立情感连接
  - 设计情感共鸣点
  - 为爽感或反转做准备

- **节奏把控**
  - 开场要快，快速抓住读者
  - 铺垫要简洁，不拖沓
  - 冲突要密集，保持高强度

#### 阶段3：内容创作与优化

**步骤3.1：快速创作**
```
开场 → 铺垫 → 冲突 → 高潮 → 收尾
```

- **开场**
  - 使用钩子库的强力开场
  - 快速建立场景和人物
  - 抛出核心悬念

- **铺垫**
  - 简洁交代背景和动机
  - 建立人物形象和关系
  - 为冲突和高潮做铺垫

- **冲突**
  - 应用三问原则循环2-3次
  - 确保每次冲突都升级
  - 制造情感波动

- **高潮**
  - 设计情感爆发点
  - 可以是冲突解决、真相揭示、反转降临
  - 确保有足够的冲击力

- **收尾**
  - 快速收尾，不拖泥带水
  - 可以留下悬念或开放式结局
  - 强化主题或情感

**步骤3.2：爆款优化**
```
钩子密度 → 爽点强化 → 反转冲击 → 语言精炼 → 节奏优化
```

- **钩子密度**
  - 确保每段都有钩子
  - 增加段落间的悬念
  - 设计连续的情感刺激

- **爽点强化**
  - 强化情感宣泄
  - 增加反差的爽感
  - 设计爽点的高潮

- **反转冲击**
  - 优化反转的揭示方式
  - 增加反转的意外性
  - 强化反转的冲击力

- **语言精炼**
  - 删除冗余描述
  - 优化句式和节奏
  - 增强语言的感染力

- **节奏优化**
  - 确保节奏紧凑不拖沓
  - 张弛有度，持续吸引读者
  - 强化情感曲线

#### 阶段4：发布与迭代

**步骤4.1：发布准备**
```
标题优化 → 封面设计 → 推荐语撰写 → 标签设置
```

- **标题优化**
  - 参考 `references/模板工具/opening-hooks.md` 的标题模板
  - 使用"日常物+反常动因+悬问/后果"公式
  - 确保标题有吸引力但不剧透

- **封面设计**
  - 针对平台特点设计
  - 符合题材和风格
  - 有视觉冲击力

- **推荐语撰写**
  - 简洁有力
  - 突出爽点或特色
  - 激发阅读兴趣

- **标签设置**
  - 选择准确的热门标签
  - 符合平台算法推荐
  - 提高曝光率

**步骤4.2：数据监控与迭代**
```
数据监控 → 用户反馈 → 分析优化 → 迭代改进
```

- **数据监控**
  - 监控阅读量、完读率、点赞、评论
  - 分析用户的阅读行为
  - 评估爆款效果

- **用户反馈**
  - 关注评论和反馈
  - 分析用户的爽点和痛点
  - 收集改进建议

- **分析优化**
  - 分析数据和反馈
  - 找出问题和优化点
  - 制定改进计划

- **迭代改进**
  - 根据分析结果调整创作策略
  - 优化选题、风格、结构
  - 持续提升爆款率

### 流程三：AI漫剧改编（视觉化工作流）

#### 阶段1：小说分析

**步骤1.1：核心元素提取**
```
核心冲突 → 视觉元素 → 情感节点 → 节奏特点 → 对话风格
```

- **核心冲突**
  - 识别主线冲突和关键转折
  - 分析冲突的视觉表现力
  - 确定改编的核心场景

- **视觉元素**
  - 提取适合视觉化的场景
  - 识别关键的视觉符号和道具
  - 分析环境和人物的视觉特点

- **情感节点**
  - 识别情感高潮和低谷
  - 分析情感变化的节点
  - 确定需要强化的情感表现

- **节奏特点**
  - 分析小说的叙事节奏
  - 识别快慢节奏的切换点
  - 适配漫剧的节奏特点

- **对话风格**
  - 分析人物的语言风格
  - 识别精彩的对话和金句
  - 确保改编后保持风格

**步骤1.2：改编评估**
```
改编可行性 → 视觉化潜力 → 剧情精简 → 保留核心 → 增强表现
```

- **改编可行性**
  - 评估小说是否适合漫剧化
  - 识别需要调整的部分
  - 制定改编策略

- **视觉化潜力**
  - 评估场景的视觉冲击力
  - 识别需要增强的视觉元素
  - 设计视觉化表达

- **剧情精简**
  - 确定需要保留的核心剧情
  - 设计剧情的精简和合并
  - 确保故事连贯性

- **保留核心**
  - 保留核心冲突和人物关系
  - 保留关键的爽点和情感点
  - 确保改编不丢失精髓

- **增强表现**
  - 增强视觉表现力
  - 增强情感冲击力
  - 增强节奏的紧凑性

#### 阶段2：分镜拆解

**步骤2.1：场景拆解**
```
关键场景识别 → 镜头设计 → 动作规划 → 对话转化 → 特效需求
```

- **关键场景识别**
  - 确定需要重点表现的核心场景
  - 识别情感高潮和视觉冲击力强的场景
  - 设计场景的出场顺序

- **镜头设计**
  - 设计每个场景的镜头语言
  - 确定景别、角度、运动
  - 设计镜头的切换和衔接

- **动作规划**
  - 设计人物的动作和表演
  - 设计关键的动作场面
  - 确保动作有视觉冲击力

- **对话转化**
  - 将小说对话转化为台词
  - 精简冗长的对话
  - 突出金句和情感表达

- **特效需求**
  - 识别需要特效的场景
  - 设计特效的表现方式
  - 评估特效的可行性

**步骤2.2：分镜脚本生成**
```
分镜表制作 → 画面描述 → 对话标注 → 音效设计 → 时长控制
```

- **分镜表制作**
  - 创建详细的分镜表
  - 标注每个镜头的画面、人物、动作
  - 设计镜头的时序和切换

- **画面描述**
  - 详细描述每个镜头的画面
  - 确定构图、色彩、光影
  - 确保画面有视觉冲击力

- **对话标注**
  - 标注每个镜头的对话
  - 标注人物的表情和语气
  - 确保对话与画面配合

- **音效设计**
  - 设计背景音乐和音效
  - 确定音效的进场和退场
  - 确保音效增强情感表现

- **时长控制**
  - 控制每个场景和镜头的时长
  - 确保整体节奏紧凑
  - 符合漫剧的时长要求

#### 阶段3：节奏适配

**步骤3.1：节奏调整**
```
快慢切换 → 高潮强化 → 情感铺垫 → 悬念设置 → 收尾优化
```

- **快慢切换**
  - 设计快慢节奏的切换点
  - 快节奏用于冲突和动作
  - 慢节奏用于情感和铺垫

- **高潮强化**

## 关键原则

### 创作原则

1. **人物真实性**：基于心理学构建角色，避免脸谱化和工具化
2. **冲突驱动力**：故事必须由真实的内在冲突驱动，而非外部事件堆砌
3. **情感共鸣**：注重读者的情感体验，而非炫技或自嗨
4. **逻辑自洽**：世界观和人物行为必须符合内在逻辑
5. **风格统一**：长篇创作必须保持风格的一致性

### 技术原则

1. **记忆驱动创作**：创作前先唤醒记忆，创作后必回填记忆
2. **防漂移优先**：风格漂移和OOC比内容错误更危险
3. **分层记忆管理**：active/warm/archive分层，避免信息过载
4. **结构化数据**：用结构化摘要代替全文存储，提高效率
5. **定期体检**：每5-10章做一次全面检查和优化

### 风格原则

1. **风格服务于故事**：选择风格要考虑题材和受众
2. **毒舌有底线**：犀利观点必须基于事实和逻辑，避免无脑喷
3. **人性不等于软弱**：真实的人性包括坚强、软弱、善良、阴暗
4. **爽感需要铺垫**：爽点必须有足够的情感积累
5. **钩子要精准**：开场和章节钩子要针对目标读者

## 故障排除

### 常见问题

**Q: 长篇写到后面感觉人物跑偏了？**

A: 使用 character_consistency_checker.py 检查，然后根据检查结果修正角色档案或剧情记忆。如果问题严重，可能需要重新提取风格DNA。

**Q: 风格感觉不太统一？**

A: 使用 style_calibrator.py 进行风格漂移检测，找出偏离的部分。可以参考 style_dna_format.md 理解风格特征，然后调整写作风格。

**Q: 记忆系统越来越慢？**

A: 执行记忆优化，将过期的内容归档。参考 memory-optimization-playbook.md 了解如何分层管理记忆。

**Q: 短篇总是写不出爆款感？**

A: 检查开场钩子是否足够强力，高潮设计是否有足够的情感冲击力，反转是否在预期之外又在情理之中。参考 opening-hooks.md 和 short-story-template.md。
