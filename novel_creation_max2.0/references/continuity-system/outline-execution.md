## 概述

### 什么是细纲执行记录

细纲执行记录用于追踪正文创作与细纲规划的对照情况，保障长篇连贯性。

| 作用 | 说明 |
|------|------|
| 追踪主节点 | 记录主节点的规划与执行情况 |
| 识别偏差 | 及时发现正文与细纲的差异 |
| 支持复盘 | 为复盘提供历史数据 |
| 保障连贯性 | 确保故事脉络清晰 |

### 与其他状态文件的关系

| 文件 | 内容 | 更新频率 |
|------|------|---------|
| 当前进度.md | 卷目进度、章节进度 | 每章更新 |
| 细纲执行记录.md | 主节点规划、章节执行对比 | 每章更新 |
| 人物状态表.md | 人物当前状态 | 涉及人物时更新 |
| 时间线.md | 事件时间线 | 涉及时间时更新 |
| 伏笔清单.md | 伏笔追踪 | 涉及伏笔时更新 |

## 主节点规划格式

在每卷开始时，记录本卷的主节点规划：

```markdown
# 细纲执行记录

## 第一卷主节点规划

| 序号 | 主节点类型 | 章节位置 | 事件描述 | 状态 |
|-----|-----------|---------|---------|-----|
| M1 | 开篇锚点 | 第1-3章 | 穿越危机，系统激活 | 待执行 |
| M2 | 关键转折 | 第10章 | 第一次系统任务 | 待执行 |
| M3 | 高潮事件 | 第30章 | 外门大比打脸 | 待执行 |
| M4 | 卷末收束 | 第60章 | 离开青云宗 | 待执行 |

### 主节点详细说明

**M1 - 开篇锚点（第1-3章）**
- 核心事件：主角穿越到死前一刻，系统激活，完成第一个任务保命
- 关键设定：金手指揭示、主角处境、核心冲突引入

**M2 - 关键转折（第10章）**
- 核心事件：完成第一个重要系统任务，获得关键道具
- 关键设定：展示系统的坑货属性，建立主角与系统关系

**M3 - 高潮事件（第30章）**
- 核心事件：外门大比，主角打脸原著主角
- 关键设定：阶段性高潮，验证主角成长

**M4 - 卷末收束（第60章）**
- 核心事件：主角离开青云宗，进入更大世界
- 关键设定：收束本卷伏笔，开启下一卷
```

### 主节点状态说明

| 状态 | 说明 |
|------|------|
| 待执行 | 尚未开始写作 |
| 进行中 | 正在写作 |
| ✓ 已完成 | 已完成，无偏差 |
| ⚠ 有偏差 | 已完成，但有偏差 |

## 章节执行记录格式

每章完成后，记录执行情况：

```markdown
---

## 第1章执行记录

**章节名称**：炮灰的觉醒
**章节类型**：【主节点】M1
**执行日期**：[日期]

### 执行对比

| 项目 | 细纲规划 | 实际执行 | 差异说明 |
|-----|---------|---------|---------|
| 主要内容 | 穿越危机，系统激活 | 穿越危机，系统激活 | 无差异 |
| 核心事件 | 主角获得系统 | 主角获得系统 | 无差异 |
| 人物状态 | 主角惊恐 | 主角惊恐+搞笑内心戏 | 增强喜剧效果 |

### 执行状态

- **状态**：✓ 一致
- **说明**：按细纲执行，无偏差

---

## 第2章执行记录

**章节名称**：求生的第一步
**章节类型**：【灵活区】
**执行日期**：[日期]

### 执行对比

| 项目 | 细纲规划 | 实际执行 | 差异说明 |
|-----|---------|---------|---------|
| 主要内容 | 铺垫宗门环境 | 增加了与小配角的冲突 | 增强戏剧性 |
| 核心事件 | 日常探索 | 日常探索+小冲突 | 灵活调整 |

### 执行状态

- **状态**：✓ 灵活区调整
- **说明**：不涉及主节点，已记录差异

---

## 第10章执行记录

**章节名称**：第一次重要任务
**章节类型**：【主节点】M2
**执行日期**：[日期]

### 执行对比

| 项目 | 细纲规划 | 实际执行 | 差异说明 |
|-----|---------|---------|---------|
| 主要内容 | 完成系统任务，获得筑基丹 | 任务失败，获得其他奖励 | 主节点偏离 |
| 核心事件 | 获得筑基丹 | 获得神秘玉佩 | 改变奖励内容 |

### 执行状态

- **状态**：⚠ 主节点偏离
- **用户决策**：接受偏离
- **后续调整**：需要在后续章节补充筑基丹获取途径
- **主节点状态更新**：M2 标记为"⚠ 有偏差"
```

---

## 更新时机

| 时机 | 操作 |
|------|------|
| 每章完成后 | 添加章节执行记录 |
| 主节点偏离时 | 更新主节点状态，记录用户决策 |
| 卷末复盘时 | 检查所有主节点完成情况 |
| 开始新卷时 | 添加新卷主节点规划 |
