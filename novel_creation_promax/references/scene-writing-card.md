# 场景写作卡（Scene Writing Card）

> **用途**：每场戏开始前生成结构化约束包，让 AI 在写作时聚焦，同时明确章节边界，防止蹭到下一章。

## 模板

```
═══════════════════════════════════════
【场景写作卡】第 {N} 场 / 共 {M} 场
═══════════════════════════════════════

【基本信息】
时间/地点：
出场角色：
场景氛围：

【本场目标】
本场核心任务：
读者期待：

【字数预算】⚠️ 重要
本场预算：
本场至少要完成的过程链：观察 / 试探 / 交锋 / 结果 / 代价 / 新线索（按需勾选）
如果本场写完仍不足本章目标字数，不是收尾，而是补足缺失过程

【章节截断点】⚠️ 重要
本章在完成本场戏后结束。
截断信号：本场结束时会发生 → {具体事件}
下一章从 → {下一章开场事件} 开始

【本场禁止事项】🚫
- 不能出现：
- 不能发生：
- 不能透露：

【角色状态快照】
{角色A}：当前位置 / 情绪状态 / 持有物品
{角色B}：当前位置 / 情绪状态 / 持有物品

【上一场结尾】
{上场的关键结尾事件}

═══════════════════════════════════════
```

## 使用说明

### 什么时候生成？

- **每章开始前**：生成全章的场景写作卡（可能有多场戏）
- **每场戏开始时**：从记忆中提取当前场的卡片，作为写作提示

### 字数预算怎么填？

番茄默认把一章拆成 5-6 场，每场建议 450-650 中文字符。不要把“总字数要求”压成一句抽象指令，而要把字数分配到每场：

```
第1场：450-550（承接上章 + 目标出现）
第2场：450-550（第一次阻力）
第3场：500-650（试探/交锋）
第4场：450-550（代价/误判）
第5场：500-650（爽点兑现）
第6场：450-550（章末钩子）
```

如果第3场还没出现真正交锋、第4场还没出现代价，就算字数看起来够了，也视为结构不完整；反过来如果结构完整但字数不足，就补“过程”，不要补重复解释。

### 章节截断点为什么重要？

```
错误做法：
  写完本场戏后，AI 继续往下写下一章的内容
  → 导致两章内容混在一起，逻辑混乱

正确做法：
  明确告诉 AI："本场戏结束 = 本章结束"
  → AI 在截断点自然停笔
```

### 本场禁止事项怎么写？

不要写得太泛。越具体越好：

```
❌ 不好："不能有废话对话"
✅ 好："不能有'嗯'、'那'、'好吧'这种不推动信息的语气词"

❌ 不好："不能剧透"
✅ 好："不能透露反派真实身份"
```

## 示例：都市总裁文场景

```
═══════════════════════════════════════
【场景写作卡】第 3 场 / 共 4 场
═══════════════════════════════════════

【基本信息】
时间/地点：晚上9点 / 顾氏集团总裁办公室
出场角色：顾深（男主）、林晚（女主）
场景氛围：紧张对峙，暗流涌动

【本场目标】
本场核心任务：女主发现男主桌上有一份离婚协议书
读者期待：读者想知道女主会怎么反应

【章节截断点】⚠️ 重要
本章在女主拿起离婚协议后结束。
截断信号：女主翻开协议书第一页
下一章从 → 女主看到协议书上的日期开始

【本场禁止事项】🚫
- 不能出现：男主突然解释离婚原因
- 不能发生：女主当场崩溃大哭
- 不能透露：协议书是男主设的局

【角色状态快照】
顾深：办公室内 / 表面冷漠，内心观察 / 手持威士忌
林晚：刚进门 / 愤怒但克制 / 手里拎着给男主的晚餐

【上一场结尾】
女主临时决定去公司给男主送晚餐，没打招呼直接上楼

═══════════════════════════════════════
```

## 与记忆系统的结合

场景写作卡从 `memory/context.json` 中提取以下信息生成：

- 当前章节号和总场次
- 出场角色及其当前状态
- 上章结尾事件
- 下章开场预告

生成命令：

```bash
python novel_creation_promax/novel-memory-pro/scripts/memory_manager.py \
  scene-card \
  --chapter N \
  --memory-dir novel_output/{平台}/{小说名}/memory
```
